# Контракт Welcome

Welcome владеет анкетами, настройками, расходом квоты, рефералами и состоянием обработки сообщений. Auth владеет учётной записью и решением об активации. «Диалоги» владеют личной перепиской.

## Входы

- POST /telegram принимает проверенный адаптером приватный Telegram update в виде JSON. Секрет входит в Authorization Bearer. Бот, update, отправитель и тема задают устойчивые ключи. Поле kind принимает text, file, audio или callback. Ответ содержит текст, решение об озвучке, необязательную кнопку и артефакты.
- POST /telegram-audio принимает байты краткого аудио. Проверенные метаданные update передаются в x-brai-welcome-event, JSON в base64url. Подпись и данные отклонённых файлов в запрос не входят. Сервис проверяет фактическую длительность перед расшифровкой.
- GET /media возвращает готовый выходной артефакт только при совпадении Auth владельца. Ключ авторизации тот же, что у приватного Telegram-входа.
- POST /admin получает cookie администратора и известный Origin. Операции settings, visitors, chats, messages и applications читают настройки или данные. save-settings и decision выполняют запись. Действующая роль проверяется через Auth при каждом обращении.
- GET /health подтверждает доступность установленной БД.

## Запись и восстановление

Для одного владельца PostgreSQL сериализует обработку обновлений. При повторе сохранённого update ответ и ID вызовов MCP переиспользуются. Квоты считаются отдельно на человека по времени БД за скользящие 24 часа. Доступ администратора и решения фиксируются в аудите.

Модель получает Markdown-справку, текущий текст и личный контекст. Она возвращает структурированное предложение. Вызовы MCP, генерация артефактов и изменения доступа доступны только сервису.
