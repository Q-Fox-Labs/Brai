# Brai для Hermes

Node ESM программы соединяют нативный Hermes с действующими сервисами Brai. Пакеты уже входят в workspace; отдельная установка не нужна. Серверные адреса, секреты и каталоги задаёт конфигурация экземпляра. Программы не запускают основной Brai Agent.

## Создание Excel

Системный навык [spreadsheets](../../docs/user-agent/instructions/hermes/skills/office/spreadsheets/SKILL.md)
использует готовый stdlib helper из extensions/skill-scripts/office/spreadsheets/scripts/xlsx.py.
Вход — листы с рядами типизированных значений; выход — настоящий XLSX для обычной
публикации через Artifacts. Формулы, макросы и редактирование существующих книг
не поддерживаются. Пакеты Python и внешний сервис не требуются.
Скрипт входит в код компонента; текст навыка устанавливается отдельно.

## Установка экземпляра

Локальный оператор выпуска поставляет адаптеры Brai как проверенный неизменяемый payload. Нативный движок Hermes, MemOS, Hermes package manager (PM), Python bridge-venv и остальные внешние службы подготавливает оператор по своему lifecycle; они не входят в payload адаптеров. Для экземпляра нужны закреплённые версии и совместимые зависимости, указанные в `component.json`. Установка адаптеров не устанавливает и не обновляет внешний движок.

Для независимых окружений оператор задаёт отдельные корни engine, runtime, профиля и защищённых учётных данных. Профиль содержит состояние и пользовательские данные; engine и runtime содержат программное окружение. Доступы, рабочие каталоги, сетевые настройки и владельцы настраиваются для каждого экземпляра. Смена поставки не переносит автоматически профиль или credentials другого окружения.

Операторские описания `brai-hermes-native-v1` и `brai-hermes-instance-v2` относятся к разным форматам установки. Существующий экземпляр v1 сохраняет своё размещение и остаётся поддерживаемым; v2 описывает отдельный экземпляр с закреплённой идентичностью поставки. Выбор v2 не преобразует и не переключает v1 автоматически. Перед применением оператор проверяет совместимость описания, путей, прав и фактического runtime своего экземпляра.

## Разрешения и название

Пользовательское имя — Brai. Управляемые расширения добавляют разговорное
согласование: разрешённая работа выполняется самостоятельно, существенные
непорученные последствия требуют обычного вопроса. Технические карточки
и широкие кнопки разрешений в этом режиме не используются.
Настройки и границы — в [контракте](CONTRACT.md#разговорные-разрешения-и-имя-brai).
Включение DEV требует отдельной приёмки; PROD автоматически не переключается.

## Запуск

Перед запуском должны быть собраны сервисы Agent и его publisher. Доступы Hermes к NATS и Transcription задаются отдельно от доступов отключаемого Agent.

```sh
BRAI_HERMES_CONFIG=/absolute/private/hermes.json \
BRAI_HERMES_OWNER_ID=canonical-owner \
node services/hermes/tools.mjs
```

В конфигурации Hermes этот процесс подключается как MCP stdio сервер. В stdout идёт только MCP. Обязательная защищённая конфигурация:

```json
{
  "ownerId": "canonical-owner",
  "nats": {
    "servers": ["nats://broker.internal:4222"],
    "user": "hermes",
    "password": "provided-by-runtime",
    "inboxPrefix": "_INBOX.brai_hermes"
  },
  "gameCore": {
    "url": "http://game-core.internal:8080/mcp",
    "ownerId": "canonical-owner"
  },
  "history": { "url": "http://history.internal:8080/mcp" },
  "transcription": {
    "url": "http://transcription.internal:8080/mcp",
    "token": "provided-by-runtime"
  },
  "publisher": { "configPath": "/absolute/private/publisher.json" },
  "requestTimeoutMs": 12000,
  "longRequestTimeoutMs": 300000,
  "tts": {
    "model": {
      "modelId": "silero-tts-ru-v5_5",
      "revision": "50081637b602126ee06cb3bc8a744d25651d2da1",
      "profileId": "silero_pytorch"
    }
  },
  "stt": {
    "model": {
      "modelId": "gigaam-v3-e2e-ctc",
      "revision": "cec030b4c4f35d928e4a9044a3bdb29ebd499fac",
      "profileId": "gigaam_pytorch"
    }
  }
}
```

`gameCore.ownerId` подтверждает привязку доверенного owner-bound endpoint. Он должен совпадать с владельцем конфигурации самого GameCore и `BRAI_HERMES_OWNER_ID`. Transcription bearer должен быть заранее привязан владельцем сервиса к тому же owner. Модель не передаёт owner ни одному инструменту. Параметр `publisher.entrypoint` позволяет явно указать абсолютный путь к готовому `publisher-mcp.js`; по умолчанию используется соседний `services/agent/dist/publisher-mcp.js`.

Конфигурация publisher описана в [PUBLISHER.md](../agent/PUBLISHER.md). Его `resultRoot` должен совпадать с `BRAI_TELEGRAM_RESULT_ROOT`; `allowedReadRoots` включают только рабочие каталоги Hermes, которые можно публиковать. Не добавляйте секретные каталоги. Веса моделей и базы сервисов не относятся к результатам агента.

## Файлы во всех режимах

Все пользовательские файлы постоянно хранятся в Artifacts. Общий адаптер и обязательный patch движка подключаются Ansible из принятой поставки для каналов, CLI/API, cron и дочерних агентов. Явные наборы сохраняют порядок, подписи и способ выдачи. [Контракт и приёмка](files/CONTRACT.md).

Готовые изображения, голос, видео и снимки браузера из штатного native cache сначала передаются в рабочую область текущего хода, затем публикуются через защищённый snapshot и возвращаются в `results` для доставки. Списки голосовых файлов, теги отправки и словарь native vision сохраняют опубликованные пути. Настройки publisher, разрешённые корни и файловый RPC сохраняют прежний формат. Проверка `files/tests/identity.test.mjs` использует также точные функции закреплённого native source при заданном `BRAI_ENGINE_TEST_ROOT`.

Большие ответы инструментов (`cache/spillover`), полные веб-страницы и дерево браузера, вывод терминала/code execution, результаты делегирования, hooks и дерево computer use читаются через проверенную readonly копию своего хода без публикации в Artifacts. Точные native каталоги и прежние имена перечислены в [файловом контракте](files/CONTRACT.md#служебные-ответы-и-справочники). Снимки `computer_use` публикуются как готовые снимки. Справочники `skill_view` сохраняют пути относительно пакета навыка; прямое чтение общих инструкций использует защищённое поколение документов. Корни публикации и owner RPC остаются прежними.

## Telegram и голос

Одиночный профиль Hermes принимает сообщения в личке и настроенной группе.
При обновлении прежние групповые темы используют сохранённые сессии Hermes.
[Маршрут и совместимость](telegram/CONTRACT.md#конфигурация-и-границы).

Первое сообщение новой неявно названной темы в личке или настроенной форумной
супергруппе запускает `telegram/topic_names.py`. Переменная
`BRAI_TELEGRAM_TOPIC_SOCKET` указывает на [закрытый сокет Диалогов](../dialogues/README.md#названия-тем-telegram).
Диалоги запускают временный запрос к подписочной Luna в штатном Codex App Server.
Значок выбирается из списка Telegram; сопоставление с его ID остаётся в плагине.
Плагин применяет результат к исходной теме в фоне. Явно названные темы не
переименовываются. Ошибка не прерывает ответ; повтор неизвестной попытки не
производится. Учёт первого сообщения хранится в существующей SQLite плагина.
Identity ingress — отдельный режим, этот механизм к нему не подключён.

В такой установке инструмент `telegram_rename_current_topic` в MCP Brai
принимает `title` для готового заголовка или `text` с кратким описанием темы
для генератора Диалогов. Оба варианта меняют имя и сохраняют значок. Шлюз
связывает вызов с текущим Telegram-сеансом и выдаёт одноразовый допуск.
Канал инструмента настраивается переменной `BRAI_TELEGRAM_RENAME_SOCKET`.


Доверенный Telegram плагин запускает `node services/hermes/trusted.mjs` с теми же двумя переменными окружения. Он использует ограниченный JSON-RPC stdio, описанный в [CONTRACT.md](CONTRACT.md) и [trusted.openrpc.json](trusted.openrpc.json). Этот процесс нельзя регистрировать как инструмент модели.

Нативные инструменты плагина: `brai_telegram_request_confirmation`,
`brai_telegram_submit_feedback` и `brai_telegram_submit_result`. Плагин использует
`pre_gateway_dispatch` для owner/session контекста, `post_tool_call` для точной
фиксации agent attempts, а `on_session_end` и `agent_loop_stopped` — для fail
только после terminal stop. Manifest перечисляет весь этот публичный lifecycle;
vendor Hermes не меняется. Практические результаты берутся только из текущего
сообщения владельца и сохраняют его provenance.

Сообщения о завершившихся ошибкой запросах в Telegram формируются на русском по классификации движка. Они показывают причину и доступные действия, известное время снятия лимита и предупреждение о возможных выполненных действиях. Подтверждённый ответ подписочного подключения `openai-codex` с HTTP 429 и структурированным признаком `usage_limit_reached` показывается как исчерпание лимита подписки на ИИ-размышления. Сам по себе HTTP 429 не подтверждает исчерпание подписки. Сообщения предлагают продолжить обычным текстом, без команд. Тип подключения определяется по фактическому адресу и выбранному сервису после возможного переключения модели; для неподтверждённого адреса место сбоя остаётся неизвестным. Уже выданная часть ответа сохраняется; исходное сообщение об ошибке не добавляется в чат. Очищенная диагностика записывается в журнал с номером для проверки. Когда движок передаёт исходное сообщение об ошибке отдельно от ответа, запись сохраняет его, а также доступные HTTP-код, число попыток, модель, сервис и время снятия лимита. Текстовые поля ограничены 8192 знаками; усечение отмечается в записи. Уже выданная часть ответа не добавляется в исходное сообщение об ошибке. Если причина неизвестна, сообщение не предполагает её. Другие каналы и отдельные уведомления используют собственные сообщения.

Уведомления о повторной доставке, длительной работе, остановке и сокращении истории выводятся по-русски. При остановке предупреждение получают только разговоры с работающими агентами; домашние каналы отдельно не оповещаются. После запуска отдельное сообщение о возвращении не отправляется: прерванная работа продолжается автоматически, а её ответ доставляется в исходный разговор. Причина возможного повтора сохраняется: перезапуск, восстановление соединения или отказ платформы из-за частоты отправки. В сообщениях о ходе работы внутреннее описание активности заменяется понятным этапом; исходный статус остаётся в диагностике. Английские диагностические статусы движка для чатовых каналов представляются по известной категории, а неизвестные — общим русским уведомлением; исходная очищенная от секретов диагностика записывается в журнал. Программные каналы сохраняют исходные статусы. Старые служебные записи о незавершённых ходах по-прежнему распознаются. Текст самого ответа и вложения пользователя не переводятся автоматически.

Прямые уведомления gateway о фоновых процессах не содержат команд и сырого вывода. При сбое в обычный журнал записываются очищенная диагностика и номер; прямое уведомление и событие агенту содержат понятный статус и номер без команды и сырого вывода. Успешный результат передаётся агенту. Асинхронный журнал не подтверждает запись на диск в момент выдачи номера.

Промежуточные пояснения модели в личном Telegram начинаются с «⏳ Работаю:» и отправляются без звукового уведомления. Периодические сообщения по таймеру отключены; итог и предупреждения сохраняют обычный порядок доставки. Частоту пояснений определяет модель: во время одного долгого вызова инструмента новых сообщений может не быть.

Для Codex app-server промежуточными считаются только сообщения с подтверждённой фазой пояснения. Если фаза не указана, текст ожидает завершения хода; при обрыве полученная часть показывается с сообщением о незавершённой работе. Частичный ответ, повторённый в начале итога, не дублируется. При разбиении длинных сообщений Telegram сохраняются текст, жирное выделение и кодовые блоки.

Автоматические сводки фоновых изменений навыков и памяти по умолчанию отключены и в существующих личных профилях; сами фоновые проверки продолжаются. Явная настройка профиля сохраняет приоритет. Отключение также скрывает предложения фоновой проверки, требующие подтверждения.

Поиск и чтение страниц выбирают источники отдельно. Если автоматический выбор чтения ошибочно возвращает предназначенный только для поиска Codex CLI, используется доступный встроенный Firecrawl без ключа. Явный выбор источника чтения сохраняется. Внешний сервис получает адрес запрошенной страницы; при его отказе агент сообщает об ошибке чтения.

Telegram Business обрабатывает отдельный установленный плагин: фильтр Brai пропускает его lifecycle, сохраняя запрет доступа Business-сообщений к общему диалогу и human решениям Brai. Подключение допускается только для основного владельца. Черновик приходит владельцу для подтверждения; автоматической отправки собеседнику нет. Граница dispatch описана в [контракте Telegram](telegram/CONTRACT.md).

`voice.mjs --input /absolute/text.txt --output /absolute/speech.ogg --voice eugene` подключает нативный tts Hermes к Local AI. Вход — UTF-8 файл с текстом до 900 Unicode code points; выбранная модель приходит из `tts.model`. Результат получает Artifacts ID и восстанавливается через publisher с проверкой owner/hash. Готовый OGG копируется в незанятый путь output. Timeout не вызывает автоматический новый синтез.

Инструмент `local_ai_invoke_synthesize`, доступный модели через MCP, принимает только текст. Модель, голос, идентификаторы и срок выбирает мост. Подробности и обработка неизвестного исхода — в [контракте](CONTRACT.md#выполнение-и-неизвестный-исход).

`transcribe.mjs --input /absolute/voice.ogg --output /absolute/transcript.txt` подключает нативный command STT к существующему Transcription/GigaAM без нового ключа. Входной обычный файл должен находиться в `allowedReadRoots` publisher; publisher автоматически распознаёт OGG/Opus или Vorbis, WAV и FLAC по байтам. MP3 распознаётся publisher по заголовку ID3v2 или MPEG Layer III и передаётся как `audio/mpeg`; произвольный `application/octet-stream` мост не принимает. Мост публикует файл, один раз отправляет required local submit, читает состояние и эфемерный результат через MCP, затем создаёт новый UTF-8 output с правами `0600`. Полный фактический selector проверяется против `stt.model`. Общий срок публикации и расшифровки — 180 секунд. Неизвестный исход или утрата результата не запускают повтор; выходной файл не перезаписывается. Текст ASR не проходит отдельную LLM-нормализацию. В управляемом личном worker модель и провайдер STT читаются из защищённой настройки профиля. Старый локальный YAML не отключает настроенную оператором расшифровку.

Пример секции нативного `config.yaml` Hermes, отдельного от защищённого JSON мостов выше:

```yaml
stt:
  enabled: true
  provider: brai_local_ai
  providers:
    brai_local_ai:
      type: command
      command: '/usr/local/bin/node /absolute/hermes/brai/services/hermes/transcribe.mjs --input {input_path} --output {output_path}'
      output_format: txt
      normalize: false
      timeout: 200
```

Обе переменные `BRAI_HERMES_CONFIG` и `BRAI_HERMES_OWNER_ID` нужны дочерней команде. Native timeout оставляет запас для запуска и закрытия подключений. До включения проверьте установленность выбранной модели, owner-bound Transcription bearer и отсутствие доступного альтернативного локального STT: нативный gateway может попытаться использовать его после отказа выбранного provider. Сам мост не выполняет fallback и не устанавливает модели. Для голосовых ответов используется существующий TTS provider и нативный режим `/voice`; слышимая доставка Telegram проверяется отдельно.

Постоянные задачи и решения хранятся в game-core/GameCore. Встроенный todo Hermes служит временной рабочей заметкой.

При нормативном отказе `game_core_planning_*` мост сохраняет этап и безопасную причину GameCore в `diagnostic`. Это позволяет исправить отклонённые данные по исходному пакету; формат описан в контракте. Автоматического повтора нет.

Рабочие инструкции требуют исправить подтверждённую ошибку входных данных и продолжить ту же попытку. Отклонённая до bind цитата проверяется независимым проверяющим по исходному пакету; связанный baseline остаётся неизменным. Ошибка аргументов или чтения отдельного файла не означает общую недоступность инструментов. Отказ доступа и неизвестный исход записи требуют отдельного разбора.

## Проверки

```sh
npm test --workspace=@brai/hermes
```

Проверки подтверждают owner boundary, запрещённые human вызовы модели, неизвестный исход и отсутствие повторов, настоящий MCP SDK, JSON-RPC, stale callbacks и голосовой файловый мост. Живые ACL, настройки владельца MCP и доставка Telegram проверяются отдельно при приёмке экземпляра.

## Рабочие инструкции пользовательского агента

Канонические тексты находятся в [документации пользовательского агента](../../docs/user-agent/README.md). component.json перечисляет базовые рабочие файлы в inputs.runtime и delivery.files. [Тексты навыков и справочники](../../docs/user-agent/skills.md), справочные карточки и usercustom не входят в payload. Скрипты навыков входят в код расширений.

Оператор собирает общие инструкции из проверенной поставки Hermes. Личные файлы профиля сохраняются отдельно и не заменяются общими текстами. Версию инструкций и конфигурации проверяют при установке и восстановлении.


Базовый комплект дополнительных инструкций — [INDEX.md](../../docs/user-agent/instructions/hermes/INDEX.md): правила, политики и промпт Telegram Business. Системные навыки устанавливает tools/skill_docs.py --system из точного Git-коммита в отдельный защищённый каталог, общий для всех личных профилей. Обновление кода не заменяет уже установленную документацию; неизвестные локальные правки останавливают её обновление. Операция текстов не запускает модель, сборку или службы.

Личный worker до native gateway закрепляет системные корни и личный create_dir. Системные имена, пути и настройки disabled не позволяют подменить или выключить общий навык. Пользовательские навыки создаются через skill_manage в собственной usercustom/userdata/skills без записи в репозиторий. Скрипты системных навыков подключаются отдельно из защищённого кода. Операция skill_manage personalize хранит полное личное дополнение к общему навыку в usercustom/userdata/skill-lessons; skill_view всегда включает его при загрузке основного текста, без отдельного поиска и без устаревшего native dedup. Общие цели отклоняются до native записи, включая batch и staged replay; самостоятельные навыки остаются только в userdata/skills. Дополнения адресуются системным корнем и относительным путём; переименование общего навыка требует явного переноса, исходный текст и обязательные политики не заменяются.

Загрузчик личного Hermes при каждом ходе подключает обязательные context.md, INDEX.md, BASE.md и BUG_HUNT.md из поставки, а context-gifs — из независимого системного каталога. Личные USER.md и SOUL.md необязательны, редактируются владельцем и не отменяют общие правила.

Общие тексты не содержат значений экземпляра. Личные отличия, память, переписка, авторизация и runtime usercustom хранятся отдельно от общей поставки. Рабочие копии не являются каноническим местом правки общих текстов.

Исходный комплект расширений Hermes находится в [extensions](extensions/README.md) и входит в поставку компонента вместе с каноническими инструкциями Brai. Внешние движки Hermes и MemOS и их окружение подготавливает и обслуживает оператор; поставка расширений не устанавливает их. История исходников указана в `services/hermes/extensions/provenance.json`.

## Работа без обязательного Game Core

Обычные поручения выполняются прямо в разговоре по актуальным инструкциям агента.
Для отключения инструментов и workflow Telegram оператор задаёт
`gameCore: {"enabled": false}` в защищённой конфигурации мостов. Мост не
подключается к Game Core, а прежние вызовы получают `GAME_CORE_DISABLED`.
Артефакты, память и другие подключённые возможности сохраняются. Данные Game Core
не удаляются и не меняются; старые кнопки не подтверждают новую работу.
[Точный контракт](CONTRACT.md#отключённый-game-core).

## Уточнения Telegram до ответа

Текст и готовые файлы пользователя уточняют текущую работу через steer, включая подготовку исходного сообщения до запуска исполнителя. Принятое до фиксации финала уточнение учитывается в том же ответе; изображения не остаются отдельной задачей после него. Редактирование сообщения текущего хода уточняет его, старого — только обновляет историю. [Границы и проверки](telegram/CONTRACT.md#уточнения-и-редактирование). Служебные события доступны в журнале, но не выводятся репликами пользователя.

Telegram получает согласованный финальный ответ после завершения native цикла. Токены отменённых черновиков не публикуются и не озвучиваются; сообщения о ходе работы остаются отдельными. Квитанция worker и сравнение исходного ID с последней редакцией защищают текущий ход от повторной доставки.

Для кружочка адаптер файлов локально преобразует готовый голос Silero в квадратные MP4 с анимацией и передаёт их как Telegram `video_note`. Для рендера нужны системные Python с NumPy и OpenCV и FFmpeg с H.264/AAC. Порядок подготовки, форматы и ошибки описаны в [файловом контракте](files/CONTRACT.md).

## GIF в разговоре

[Навык context-gifs](../../docs/user-agent/instructions/hermes/skills/creative/context-gifs/SKILL.md) задаёт выбор уместного момента, отключение и разовую просьбу. Скрипт extensions/scripts/context_gif.py сохраняет rare/off отдельно для собеседника в usercustom/userdata/settings/context-gifs. Дневной квоты нет; уместность и запрет автоматических вставок подряд относятся к инструкции агента, не к программному счётчику.

Подписочный маршрут использует выбранный openai-codex: подписочный Images endpoint получает output_format=gif, frame_count=9, frame_duration_ms=200. Поля соответствуют [исходному контракту Codex](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/images.rs). Сервер возвращает готовую анимацию; FFmpeg, листы кадров и перекодирование не используются. Точный серверный вариант Images 2.6/Flare не выбирается клиентом. При отказе переход к другому provider запрещён.

Генерация и публикация раздельны: результат требуется передать Brai publish_file. Скрипт проверяет структуру GIF и число кадров, сохраняет исходные байты в native cache; PNG вместо анимации отклоняется. Запрос ограничен 180 секундами и 14 МиБ ответа, готовый файл — 10 МиБ. Автоматических повторов нет. Генерация блокируется отдельно для scope собеседника; параллельная попытка пропускается. Сбой чтения настройки запрещает зависимую генерацию.

Нужны Python окружения Hermes с его существующим httpx и явный --engine-root, если движок не установлен как импортируемый пакет. Авторизацию, engine-root и HERMES_HOME предоставляет оператор текущего экземпляра. Новых пакетов нет. Установщик расширений подключает скрипт по manifest, сохраняя пользовательские настройки. Проверка с подменой HTTP не подтверждает доступность GIF конкретной подписке: полноценная приёмка требует тестового экземпляра и публикации настоящего ответа.

### Отдельный OpenAI API для GIF

Файл HERMES_HOME/context-gifs.json с provider=openai и абсолютным key_file явно выбирает API только для GIF. Flare 2.6 получает output_format=gif, quality=low, complexity=low, девять кадров по 200 мс. Endpoint закреплён как https://api.openai.com/v1/images/generations. API-ключ не поступает в окружение основного gateway: key_file — обычный файл без symlink, владельцем является root или текущий пользователь, доступа группы и остальных нет, размер не превышает 4096 байт. Файл содержит только ключ, не .env.

Без конфигурации helper сохраняет прежний подписочный маршрут. Ни ошибка подписки, ни ошибка API не переключают способ оплаты автоматически. Основная модель, память и штатная генерация изображений не зависят от этого файла. Настройки rare/off остаются отдельными предпочтениями собеседников. usage из API возвращается вместе с результатом; наличие usage не подтверждает запись в native аналитику сессии.

Пример конфигурации без секрета:

```json
{"provider":"openai","key_file":"/private/gif-openai.key"}
```

Подключение выполняет оператор вместе с установкой принятой версии GIF-помощника. Автотесты проверяют отдельный API endpoint, качество, сохранение точных байтов, запрет fallback и закрытые права ключа. Доступ к GIF preview проверяется реальным запросом выбранного API-аккаунта.

## Голосовой вход личных профилей

Личный Unix-профиль использует `python3 -m identity.transcribe` как command STT.
Установщик передаёт прежний явный `stt.model` из защищённого шаблона в параметры
команды. Без selector STT выключен. Установщик подключает владельческий Transcription
через Root; bearer не копируется в профиль.
Клиент проверяет готовый артефакт через broker или публикует собственное аудио,
затем подаёт оригинал или каждую часть в Transcription.
Длинное аудио из Telegram и форматы, требующие преобразования, проходят
нормализацию FFmpeg и нарезку по правилам Дневника. Broker назначает owner по UID;
Transcription проверяет принадлежность аудиоартефакта и обращается к Local AI.
Клиент сверяет ID запроса и полный selector результата.

Срок публикации и распознавания одной части — до 900 секунд. Потеря ответа не запускает
повтор. Результат записывается точными UTF-8 байтами в новый файл `0600`; старый
файл и symlink не перезаписываются. Код и selector включаются в штатный reconcile;
подготовка изменения не подключает STT в запущенных профилях. При приёмке нужны
реальный command provider, OGG из Telegram и проверка owner. Для управляемого
профиля автоматический fallback после отказа Transcription отключён.

## Личные процессы и память

[Граница пользователей](identity/README.md) связывает доверенный Telegram-вход, личный процесс Hermes и общую память MemOS. В режиме личных профилей общий бот обслуживает лички и группы через отдельный профиль каждого автора. Групповой диалог сохраняет исходный чат и тему. Этот режим включается только после проверки установки и миграции; прежняя конфигурация сама по себе его не активирует.

## Делегирование

Агент работает самостоятельно для небольших запросов и механических операций. Помощники применяются для независимых объёмных частей, большого промежуточного контекста или отдельной проверки. Начальные пределы: три помощника одновременно, один уровень вложенности, 50 итераций на помощника. Эти ограничения не задают денежный бюджет. Установщик применяет три лимита отдельно, сохраняя provider, модель и прочие настройки.

Родитель задаёт проверяемый результат и необходимые входы, проверяет ответы и не повторяет неизменное неуспешное задание без устранения причины. Технические ошибки остаются в диагностике; пользователь получает объяснение последствий от основного агента. Готовые результаты включаются до финала с подтверждением сохранения, повторы не запускают лишний ответ. [Гарантии файловой и контекстной границы](files/CONTRACT.md#делегирование-и-завершение).

Поиск и обработка памяти личных профилей используют Responses через существующий
подписочный proxy. Формат выбирается явным `router.transport: codex_responses`;
[параметры и ошибки транспорта](extensions/plugins/memos-rest/docs/routing.md)
описаны у провайдера. Общие credentials в личный профиль не передаются.

## Личные Диалоги

Защищённая секция dialogues выключена при отсутствии либо enabled=false.
Подготовка профиля задаёт enabled=true, url, token, userId и profileId.
UserId совпадает с ownerId Hermes; profileId сверяется с UID-реестром и Auth.
Эти параметры не принимаются от модели. В каталоге появляются dialogues_exchange
и dialogues_context_ack; native Hermes показывает их с префиксом mcp__brai__.

Транспорт пропускает действующий размер запросов Диалогов до 2 МиБ с учётом
оболочек. Отказ передаёт field, expected, applied и next_action. Потерянный ответ
возвращает неизвестный исход с исходным request_id. Операции не входят в общий
повтор чтений; подтверждённый 404 неизвестной MCP-сессии допускает одно восстановление.

Личный native-профиль получает обязательный протокол ввода, страниц, ACK и финала.
Worker проверяет наличие обоих инструментов до первого сообщения. Проверка
npm run test:identity дополняет основной набор регрессий Hermes.

После одиночного подтверждённого `finish` native передаёт точный сохранённый
текст в обычную доставку без ещё одного запроса к модели. Квитанция должна
совпасть по ID вызова, запроса, диалога, хода, финала и SHA-256 текста.
Это подтверждение сохранения; фактическую доставку подтверждает транспорт.

Администратор может выдать доступ по Telegram ID и отозвать его через «Админку» Web. Постоянная операция Auth исполняется существующим root broker через установленный Ansible lifecycle; повторная выдача сохраняет идентичность и данные. [Контракт доступа](identity/CONTROL.md#административная-выдача-и-отзыв-доступа).
