# Brai для Hermes

Node ESM программы соединяют нативный Hermes с действующими сервисами Brai. Пакеты уже входят в workspace; отдельная установка не нужна. Серверные адреса, секреты и каталоги задаёт конфигурация экземпляра. Программы не запускают основной Brai Agent.

## Установка экземпляра

Codeworks поставляет адаптеры Brai как проверенный неизменяемый payload. Нативный движок Hermes, MemOS, Hermes package manager (PM), Python bridge-venv и остальные внешние службы подготавливает оператор по своему lifecycle; они не входят в payload адаптеров. Для экземпляра нужны закреплённые версии и совместимые зависимости, указанные в `component.json`. Установка адаптеров не устанавливает и не обновляет внешний движок.

Для независимых окружений оператор задаёт отдельные корни engine, runtime, профиля и защищённых учётных данных. Профиль содержит состояние и пользовательские данные; engine и runtime содержат программное окружение. Доступы, рабочие каталоги, сетевые настройки и владельцы настраиваются для каждого экземпляра. Смена поставки не переносит автоматически профиль или credentials другого окружения.

Операторские описания `brai-hermes-native-v1` и `brai-hermes-instance-v2` относятся к разным форматам установки. Существующий экземпляр v1 сохраняет своё размещение и остаётся поддерживаемым; v2 описывает отдельный экземпляр с закреплённой идентичностью поставки. Выбор v2 не преобразует и не переключает v1 автоматически. Перед применением оператор проверяет совместимость описания, путей, прав и фактического runtime своего экземпляра.

## Запуск

Перед запуском должны быть собраны сервисы Agent и его publisher. Доступы Hermes к NATS и Transcription задаются отдельно от доступов отключаемого Agent.

```sh
BRAI_HERMES_CONFIG=/absolute/private/hermes.json \
BRAI_HERMES_OWNER_ID=canonical-owner \
node services/hermes/tools.mjs
```

В конфигурации Hermes этот процесс подключается как MCP stdio сервер. В stdout идёт только MCP. Обязательная защищённая конфигурация:

```json
{
  "ownerId": "canonical-owner",
  "nats": {
    "servers": ["nats://broker.internal:4222"],
    "user": "hermes",
    "password": "provided-by-runtime",
    "inboxPrefix": "_INBOX.brai_hermes"
  },
  "gameCore": {
    "url": "http://game-core.internal:8080/mcp",
    "ownerId": "canonical-owner"
  },
  "history": { "url": "http://history.internal:8080/mcp" },
  "transcription": {
    "url": "http://transcription.internal:8080/mcp",
    "token": "provided-by-runtime"
  },
  "publisher": { "configPath": "/absolute/private/publisher.json" },
  "requestTimeoutMs": 12000,
  "longRequestTimeoutMs": 300000,
  "tts": {
    "model": {
      "modelId": "silero-tts-ru-v5_5",
      "revision": "50081637b602126ee06cb3bc8a744d25651d2da1",
      "profileId": "silero_pytorch"
    }
  },
  "stt": {
    "model": {
      "modelId": "gigaam-v3-e2e-ctc",
      "revision": "cec030b4c4f35d928e4a9044a3bdb29ebd499fac",
      "profileId": "gigaam_pytorch"
    }
  }
}
```

`gameCore.ownerId` подтверждает привязку доверенного owner-bound endpoint. Он должен совпадать с владельцем конфигурации самого GameCore и `BRAI_HERMES_OWNER_ID`. Transcription bearer должен быть заранее привязан владельцем сервиса к тому же owner. Модель не передаёт owner ни одному инструменту. Параметр `publisher.entrypoint` позволяет явно указать абсолютный путь к готовому `publisher-mcp.js`; по умолчанию используется соседний `services/agent/dist/publisher-mcp.js`.

Конфигурация publisher описана в [PUBLISHER.md](../agent/PUBLISHER.md). Его `resultRoot` должен совпадать с `BRAI_TELEGRAM_RESULT_ROOT`; `allowedReadRoots` включают только рабочие каталоги Hermes, которые можно публиковать. Не добавляйте секретные каталоги. Веса моделей и базы сервисов не относятся к результатам агента.

## Файлы во всех режимах

Все пользовательские файлы постоянно хранятся в Artifacts. Общий адаптер и обязательный patch движка подключаются Ansible из принятой поставки для каналов, CLI/API, cron и дочерних агентов. Явные наборы сохраняют порядок, подписи и способ выдачи. [Контракт и приёмка](files/CONTRACT.md).

## Telegram и голос

Доверенный Telegram плагин запускает `node services/hermes/trusted.mjs` с теми же двумя переменными окружения. Он использует ограниченный JSON-RPC stdio, описанный в [CONTRACT.md](CONTRACT.md) и [trusted.openrpc.json](trusted.openrpc.json). Этот процесс нельзя регистрировать как инструмент модели.

Нативные инструменты плагина: `brai_telegram_request_confirmation`,
`brai_telegram_submit_feedback` и `brai_telegram_submit_result`. Плагин использует
`pre_gateway_dispatch` для owner/session контекста, `post_tool_call` для точной
фиксации agent attempts, а `on_session_end` и `agent_loop_stopped` — для fail
только после terminal stop. Manifest перечисляет весь этот публичный lifecycle;
vendor Hermes не меняется. Практические результаты берутся только из текущего
сообщения владельца и сохраняют его provenance.

Сообщения о завершившихся ошибкой запросах в Telegram формируются на русском по классификации движка. Они показывают причину и доступные действия, известное время снятия лимита и предупреждение о возможных выполненных действиях. Тип подключения определяется по фактическому адресу и выбранному сервису после возможного переключения модели; для неподтверждённого адреса место сбоя остаётся неизвестным. Уже выданная часть ответа сохраняется; исходное сообщение об ошибке не добавляется в чат. Очищенная диагностика записывается в журнал с номером для проверки. Когда движок передаёт исходное сообщение об ошибке отдельно от ответа, запись сохраняет его, а также доступные HTTP-код, число попыток, модель, сервис и время снятия лимита. Текстовые поля ограничены 8192 знаками; усечение отмечается в записи. Уже выданная часть ответа не добавляется в исходное сообщение об ошибке. Если причина неизвестна, сообщение не предполагает её. Другие каналы и отдельные уведомления используют собственные сообщения.

Telegram Business обрабатывает отдельный установленный плагин: фильтр Brai пропускает его lifecycle, сохраняя запрет доступа Business-сообщений к общему диалогу и human решениям Brai. Подключение допускается только для основного владельца. Черновик приходит владельцу для подтверждения; автоматической отправки собеседнику нет. Граница dispatch описана в [контракте Telegram](telegram/CONTRACT.md).

`voice.mjs --input /absolute/text.txt --output /absolute/speech.ogg --voice eugene` подключает нативный tts Hermes к Local AI. Вход — UTF-8 файл с текстом до 900 Unicode code points; выбранная модель приходит из `tts.model`. Результат получает Artifacts ID и восстанавливается через publisher с проверкой owner/hash. Готовый OGG копируется в незанятый путь output. Timeout не вызывает автоматический новый синтез.

`transcribe.mjs --input /absolute/voice.ogg --output /absolute/transcript.txt` подключает нативный command STT к существующему Transcription/GigaAM без нового ключа. Входной обычный файл должен находиться в `allowedReadRoots` publisher; publisher автоматически распознаёт OGG/Opus или Vorbis, WAV и FLAC по байтам. MP3 пока не поддержан файловым мостом: publisher не распознаёт его аудиосигнатуру, а произвольный `application/octet-stream` мост не принимает. Мост публикует файл, один раз отправляет required local submit, читает состояние и эфемерный результат через MCP, затем создаёт новый UTF-8 output с правами `0600`. Полный фактический selector проверяется против `stt.model`. Общий срок публикации и расшифровки — 180 секунд. Неизвестный исход или утрата результата не запускают повтор; выходной файл не перезаписывается. Текст ASR не проходит отдельную LLM-нормализацию.

Пример секции нативного `config.yaml` Hermes, отдельного от защищённого JSON мостов выше:

```yaml
stt:
  enabled: true
  provider: brai_local_ai
  providers:
    brai_local_ai:
      type: command
      command: '/usr/local/bin/node /absolute/hermes/brai/services/hermes/transcribe.mjs --input {input_path} --output {output_path}'
      output_format: txt
      normalize: false
      timeout: 200
```

Обе переменные `BRAI_HERMES_CONFIG` и `BRAI_HERMES_OWNER_ID` нужны дочерней команде. Native timeout оставляет запас для запуска и закрытия подключений. До включения проверьте установленность выбранной модели, owner-bound Transcription bearer и отсутствие доступного альтернативного локального STT: нативный gateway может попытаться использовать его после отказа выбранного provider. Сам мост не выполняет fallback и не устанавливает модели. Для голосовых ответов используется существующий TTS provider и нативный режим `/voice`; слышимая доставка Telegram проверяется отдельно.

Постоянные задачи и решения хранятся в game-core/GameCore. Встроенный todo Hermes служит временной рабочей заметкой.

При нормативном отказе `game_core_planning_*` мост сохраняет этап и безопасную причину GameCore в `diagnostic`. Это позволяет исправить отклонённые данные по исходному пакету; формат описан в контракте. Автоматического повтора нет.

Рабочие инструкции требуют исправить подтверждённую ошибку входных данных и продолжить ту же попытку. Отклонённая до bind цитата проверяется независимым проверяющим по исходному пакету; связанный baseline остаётся неизменным. Ошибка аргументов или чтения отдельного файла не означает общую недоступность инструментов. Отказ доступа и неизвестный исход записи требуют отдельного разбора.

## Проверки

```sh
npm test --workspace=@brai/hermes
```

Проверки подтверждают owner boundary, запрещённые human вызовы модели, неизвестный исход и отсутствие повторов, настоящий MCP SDK, JSON-RPC, stale callbacks и голосовой файловый мост. Живые ACL, настройки владельца MCP и доставка Telegram проверяются отдельно при приёмке экземпляра.

## Рабочие инструкции пользовательского агента

Канонические тексты находятся в [документации пользовательского агента](../../docs/user-agent/README.md). component.json перечисляет отдельные рабочие файлы в inputs.runtime и delivery.files; справочные карточки и usercustom не входят в payload.

Оператор читает инструкции из immutable поставки Hermes с artifact-manifest.json и сверяет SHA-256 выбранных файлов. Контекст окружения добавляется отдельно. Обновление профиля заменяет только точно известный управляемый блок, сохраняя окружающий пользовательский текст. Неизвестные правки не перезаписываются. Перед применением оператор сохраняет точный обратимый набор затронутых файлов. Откат возвращает прежние инструкции и конфигурацию только при известном текущем содержимом; посторонние изменения требуют разбора. Данные профиля восстанавливать ради такого отката не нужно.


Полный комплект дополнительных инструкций — [INDEX.md](../../docs/user-agent/instructions/hermes/INDEX.md): базовые правила, политики, восемь навыков со справочниками и промпт Telegram Business. Штатный SOUL.md направляет к установленным INDEX.md и BASE.md и к личному ROUTING.md. Перенос сохраняет порядок чтения и полные действующие редакции; отдельный загрузчик не вводится.

Общие тексты не содержат значений экземпляра. Его текущие редакции, включая личные отличия, сохраняются в защищённом установленном наборе; квитанция связывает его с принятой поставкой и контрольными суммами. Код расширений, память, переписка, авторизация и runtime usercustom остаются на месте. Прежние рабочие копии служат совместимости и не являются каноническим местом правки общих текстов.

Исходный комплект расширений Hermes находится в [extensions](extensions/README.md) и входит в поставку компонента вместе с каноническими инструкциями Brai. Внешние движки Hermes и MemOS и их окружение подготавливает и обслуживает оператор; поставка расширений не устанавливает их. История исходников указана в `services/hermes/extensions/provenance.json`.
