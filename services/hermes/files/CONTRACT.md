# Пользовательские файлы Hermes

Все постоянные пользовательские байты принадлежат Artifacts. Локальные пути — временные копии. Служебные файлы, настройки, инструкции, навыки и внутренние базы остаются в штатном lifecycle. Движки экземпляров уже отдельные; адаптер их не разделяет и не копирует.

## Интерфейс и доверие

`publish_file`/`fetch_file` сохраняют совместимость. `files_get`/`files_list` используют owner-схемы Artifacts с фиксированным владельцем. `files_prepare({mode,items})` проверяет метаданные всего упорядоченного набора и возвращает `deliveryMarker`. Элемент содержит `artifactId`, необязательные `caption` и `presentation`; режим — `files` или `album`. Порядок и повтор одного файла сохраняются. Один ответ содержит один явный набор. Перед доставкой заново проверяются байты, размер, SHA-256, owner и готовность всех элементов.

Модель не задаёт owner, адрес сервиса или NATS subject. Private `files.configuration` передаёт bootstrap только root-owned конфигурацию без credentials и отсутствует в MCP модели. [OpenRPC](../trusted.openrpc.json) описывает private методы.

## Обязательные границы

Ansible применяет `native.patch` к закреплённому движку `517b5e10febd619ce30bb22580e29b160266eb43`. Bootstrap читает защищённую конфигурацию своего экземпляра. Ошибка адаптера останавливает файловую операцию. Patch охватывает общий conversation loop, tool dispatch, read/write/patch, terminal/code execution cwd, final response и канальные отправки. CLI/API, cron и дочерние агенты используют ту же границу.

CLI/API принимают локальные `@file:`/`@image:` и `artifact:<UUID>`; мультимодальные API-файлы сначала публикуются. Прямые удалённые/inline байты модели отклоняются. Канальные CDN-вложения скачиваются штатным SSRF/size-ограниченным загрузчиком, затем публикуются. Результат conversation содержит `fileSets` со стабильными ID; каналы получают отдельные временные копии конкретного ответа.

Промежуточные материалы в рабочей области автоматически не публикуются. Сохраняются явно выбранные результаты и выходы генераторов. Файловые изменения вне временной области и разрешённых служебных путей отклоняются. Терминал и code execution получают временный cwd; это правило приложения, не отдельная изоляция произвольного shell-кода.

## Приём наборов

Identity файла включает owner, канал, экземпляр, чат, тему, отправителя, исходный message ID и attachment ID исходного сообщения. Позиция позднее объединённого массива в ключ не входит. Состав, подписи, происхождение, готовность и admitted-версия хранятся в служебной SQLite Hermes; байтов там нет.

Telegram сохраняет элементы после авторизации до штатного debounce. Группировка учитывает полный маршрут и media_group_id. Поддержаны фото/видео и документы. Повтор использует прежний ключ. Перед агентом проверяется весь набор; неполный набор останавливает обработку. Поздний элемент становится дополнением; прежние элементы повторно не запускаются. После перезапуска восстанавливаются принятые не переданные наборы и неопределённые публикации с прежними ключами. Admitted означает передачу в обработку, не успешное выполнение задачи.

## Доставка и очистка

Набор получает проверенные копии и leases до первого вложения. Telegram отправляет совместимые группы по 2–10 через sendMediaGroup, большие наборы разбивает заранее, одиночный остаток отправляет отдельно. Фото/видео могут смешиваться; documents/audio группируются только со своим типом. Несовместимые сочетания, voice и animation идут по порядку отдельно с пояснением. Проверяются типы и размер. Длинные подписи сохраняются отдельным текстом без усечения; чат и тема сохраняются. [Ограничения Bot API](https://core.telegram.org/bots/api#sendmediagroup).

Перед вызовом канала записывается unknown. Квитанции каждого элемента сохраняются; sent требует подтверждения всего набора. Потеря ответа оставляет unknown с известными квитанциями, без автоматического повтора или fallback. Другие каналы преобразуют тот же набор в поддерживаемое представление.

Временные копии ответа освобождаются после потребителя/доставки. Leases защищают параллельные операции; после crash проверяется PID/start time. Неподтверждённые публикации и неизвестные доставки сохраняются для восстановления. Разрешение чтения каталога не даёт права удалить его содержимое: очистка ограничена объявленными временными путями.

## Переход и приёмка

`install.py` сохраняет UID/GID/mode/ACL движка и не запускает gateway. Прежние overlays проверяются после обратного применения только нашего delta на копии. Перенос старых материалов выполняет отдельный Ansible manifest: размер, SHA-256 и восстановление каждого файла проверяются до освобождения источников. Старые пути остаются в aliases. Служебные файлы, инструкции, навыки и секреты исключаются.

Автономные Python/Node проверки и проверка pinned patch не требуют модели. Живые CLI/API, cron, дочерний агент, Telegram и восстановление после очистки кэша входят в приёмку конкретной поставки. До принятия результата DEV не обновляется; миграция данных в этой задаче не запускается.
