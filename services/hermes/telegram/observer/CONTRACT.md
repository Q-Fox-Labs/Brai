# Наблюдение Telegram

Граница `services/hermes/telegram/observer` принадлежит Hermes и предоставляет чтение Telegram-переписки Brai. Она не отправляет сообщения и не принимает команды модели. Наблюдение включается оператором только в DEV; разрешённые пользователи веб-экземпляра видят все сохранённые личные и групповые чаты этого профиля. Business lifecycle остаётся отдельным.

Плагин фиксирует исходный разрешённый `message`/`edited_message` до обработки native очередями. Общая файловая граница добавляет к нему проверенные ссылки Artifacts и отмечает ошибку публикации. Подтверждённые ссылки сохраняются при частичном отказе. Ответы, прямые текстовые отправки бота и квитанции доставки поступают от native адаптера, Telegram Bot API и очереди доставки; повторное наблюдение одного Telegram message объединяется в одну запись; неподтверждённые отправки не называются успешными. Telegram General topic 1 приводится к пустому topic. Повтор идентичного события не создаёт новую запись. Ошибка журнала диагностируется безопасным кодом и не меняет Telegram dispatch.

Состояние хранится в `<BRAI_TELEGRAM_STATE_DIR>/observer.sqlite3` отдельно от выпуска: SQLite WAL, каталог закрыт владельцу профиля, файл mode 0600. Журнал не содержит байтов файлов. Изменения фиксируются возрастающим `seq`; чтение истории использует cursor строки и порядок времени/row_id. При перезапуске все сохранённые изменения доступны. После включения журнал автоматически импортирует доступную историю через native `SessionDB` в режиме read-only. Импорт учитывает архив и сжатые продолжения, не изменяет существующие live-записи и не подставляет неподтверждённую доставку. При временной ошибке чтение повторяется. Повторный импорт дополняет существующие записи подтверждёнными вложениями и именами, не заменяя их текст или живые данные. Старые вложения без локальной связи принимаются только по совпадению ключа публикации с владельцем и исходным Telegram-сообщением. Имена авторов общих тем, которые не сохранились отдельно, остаются неизвестными. Импорт не восстанавливает события, отсутствующие в исходной истории.

## NATS Services

Сервис `brai_hermes_telegram_observer` 1.0.0, queue group того же имени, endpoint `brai.hermes.telegram.observer.v1.query`. Транспорт и ACL задаются оператором. Для сервиса используется отдельная защищённая NATS identity из `BRAI_TELEGRAM_OBSERVER_NATS_CONFIG`; файл SQLite задаёт `BRAI_TELEGRAM_OBSERVER_DB`. Запрос и ответ — UTF-8 JSON; владелец определяется конфигурацией процесса, поля owner и произвольные операции не принимаются. Запрос до 4096 байт, ответ до 1 MiB, страница от 1 до 100 записей. При ошибке присутствуют заголовки `Nats-Service-Error` и `Nats-Service-Error-Code`. Таймаут web запроса — 2 секунды; повтор чтения не меняет данных.

| Action | Вход | Результат |
| --- | --- | --- |
| `status` | `action` | `{cursor}` — последняя сохранённая последовательность |
| `chats` | `action`, optional `limit`, `before` | `{chats,before}` — чаты и cursor следующей страницы |
| `messages` | `action`, `chatId`, `threadId`, optional `limit`, `before` | `{messages,before}` — сообщения в хронологическом порядке |
| `changes` | `action`, `after`, optional `limit` | `{changes,cursor}` — сохранённые изменения после cursor |
| `attachment` | `action`, `identity`, `artifactId` | `{allowed,ownerId?}` — связь файла с сообщением и доверенный владелец при подтверждении |

`identity` является устойчивым ключом сообщения, `row_id` — cursor страницы, `change_seq` — cursor изменений. Данные сообщения включают чат, topic, автора, направление, текст, время, состояние доставки и список `{artifactId,filename,mimeType,sizeBytes,sha256?}`. Ответ содержит только метаданные, не локальный путь файла. История может содержать неизвестного автора и `delivery=unknown`.

Web проверяет действующую сессию, разрешённый режим DEV, связь файла с сообщением и owner/ready через DEV Artifacts, в который публикует Hermes. Владелец поступает только из защищённой операторской конфигурации наблюдателя, а не из запроса браузера. Caddy отдаёт байты из этого же хранилища после проверки. SSE проверяет журнал раз в секунду и передаёт `change_seq` как event ID. После разрыва клиент продолжает с последнего ID; медленный клиент переподключается и дочитывает журнал. Входящие данные и тексты не попадают в диагностические журналы.

В интерфейсе подпись сообщения сохраняется, а служебные пути и идентификаторы подтверждённых вложений не показываются. Изображения выводятся без имён файлов; поддерживаемые браузером аудиоформаты доступны для воспроизведения.
