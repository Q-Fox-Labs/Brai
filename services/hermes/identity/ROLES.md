# Роли личного runtime

[Auth](../../auth/ROLES.md) владеет ролью и поколением доступа. Broker получает UID через SO_PEERCRED, Control сверяет текущий профиль с Auth. Назначенная роль не читается из USER/SOUL, личного config или модели.

`tool-policy.json` — поставляемая разрешающая политика. Catalog и dispatch используют одну проверку. Creator наследует административные инструменты, включая Local AI и Transcription; user сохраняет личные инструменты. Неизвестная роль закрывает каталог и вызов. Незарегистрированное имя не исполняется.

Для native имён MCP используется префикс `mcp__brai__`. Guest получает поиск, публичный браузер и генерацию отдельных артефактов через ограниченные порты. Встроенные доверенные процессы движка не являются пользовательским исполнителем. Полный фактический набор зависит от включённых компонентов; наличие кода не включает сервис.

## Native и восстановление

`native_policy.install()` выполняется до GatewayRunner. Registry фильтрует определения и проверяет фактический handler. Grant содержит роль и generation; до dispatch он сравнивается с новой проверкой principal, после исполнения поколение сверяется снова. Отказ Auth не разрешает прежний каталог. Начатое внешнее действие может оказаться необратимым; после отзыва его результат не выдаётся со старым поколением.

Во время подготовки runtime читает root-owned readonly profile-config; guest использует его и после активации. Старый личный config, dotenv, пользовательские MCP, entrypoint-плагины и каталоги исполняемых навыков не выбирают гостевую поставку. Product plugins загружаются из неизменяемых источников; SAFE_MODE не заменяет эту проверку. Разрешены обычный диалог и собственная остановка; остальные slash-команды гостю закрыты. В worker relay18080 общий CONNECT/HTTP гостю закрыт; поиск проходит только через типизированный /search/v1/query. Browser relay18081 использует отдельный Root listener для публичного HTTP/HTTPS и не получает внутренних модельных маршрутов.

Независимые загрузчики model providers, памяти, context engine, cron и computer use также исключают HOME, проект и entrypoints во время подготовки и для guest. MemOS загружается из readonly product source. Служебные Python-процессы используют `-s -P` и наследуемые `PYTHONNOUSERSITE=1`/`PYTHONSAFEPATH=1`: сохранённые user site, `.pth`, `sitecustomize` и рабочая директория не выбирают их код.

До Auth active проверяется trusted каталог и полный bootstrap. Для обычного user/admin/creator без отметки прежнего гостя восстановление откладывается: после свежего совпадения роли и generation Worker однократно перечитывает личные расширения, переподключает handlers/human bridge и запускает recovery/finish/watchers. Первый dispatch и interactive ждут отдельный барьер; admission health его не ждёт. При остановке Worker отменяет и дожидается этой задачи до освобождения peer. Изменённое поколение даёт отказ и завершение старого runtime.

Установщик останавливает worker и browser и подтверждает отсутствие процессов UID/потомков. Cron-определения сохраняются с enabled=false/paused; обратное повышение роли не включает их. У user после повышения может работать планировщик для новых заданий. Автовосстановление прежних процессов/прерванных фоновых ответов отключено защищённой отметкой. После повышения профиль получает продуктовую конфигурацию user; прежние исполняемые HOME-дополнения и настройки автоматически не включаются. Их файлы остаются данными профиля. История, память, личные тексты, навыки и файлы сохраняются.

Guest health не требует brai_login. Bootstrap возвращает rolePolicyVersion и подтверждённую роль; operational проверяет реальный зарегистрированный create_text_file и отказ terminal/login. Установщик требует require_tools=true и operational=true: metadata discovery подготовленного каталога разрешён до активации, actual dispatch и cron — только после active/applied_generation. Полный диалог и артефакт проверяются после активации; bootstrap отдельно не заменяет эту проверку.

## Ограниченный файловый порт

`create_text_file({filename,content,requestId})` принимает только безопасное имя без пути и точные UTF-8 байты до 1 МиБ. Root staging, snapshot, Artifacts owner и SHA-256 проверяются штатным publisher. Квитанция использует `artifact:ID`; native доставка получает собственный файл по ID без повторной произвольной публикации.

`read_text_file({artifactId})` читает только собственный UTF-8 артефакт до 1 МиБ. Прямой private files.publish у guest допускает лишь точные байты вложения с root-owned квитанцией ingress, привязанной к профилю, пути и хешу. Произвольный путь, подмена файла/ссылки или владельца отклоняются до Artifacts. Это сохраняет штатный ingest FileStore и его восстановление без общего файлового инструмента.

Полный перечень имён и ролей: [матрица инструментов](TOOL_MATRIX.md).

Контракты private-портов: broker.openrpc.json и control.openrpc.json. Файловой политикой владеет [Files](../files/CONTRACT.md).

После уточнения требований гостю доступны интернет-поиск, действия в личном
публичном браузере, генерация изображений/голоса и отдельные файлы через Artifacts.
Для DOCX/XLSX используются ограниченные структурные writers без исполнения кода.
Проекты, shell, произвольная запись на диск, навыки, настройки, rawCDP и JS-eval
остаются закрыты. Браузер имеет отдельные Unix-аккаунт, HOME и публичный egress;
прежний личный config и файлы worker в него не монтируются.

Резервирование использует отдельные `backup.status`/`backup.run` broker-порты: текущая роль и поколение Auth проверяются перед запуском и перед ответом. Личный процесс не получает root CLI, каталог копии, пароль или OAuth credential. Каталог скрывает эти инструменты от user/guest; прямой RPC также запрещён. Настройка и restore остаются root-only операторскими действиями.
