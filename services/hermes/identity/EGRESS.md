# Сетевая граница личного процесса

Личный worker и локальный relay работают под одним отдельным UID в одном сетевом пространстве без сетевых интерфейсов хоста. Relay слушает только `127.0.0.1:18080` и передаёт байты доверенному egress через Unix-сокет. На хосте egress определяет UID через `SO_PEERCRED`; входящие URL, содержимое, заголовки и ключи не журналируются. Сама программа не создаёт и не проверяет сетевое пространство: изоляция, маскирование сокетов и секретов и проверка установки принадлежат запуску системы.

Egress запускается как `python3 -m identity.egress --socket PATH --registry PATH --config PATH`; relay — как `python3 -m identity.network --socket PATH --port 18080`. Worker использует `HTTP_PROXY` и `HTTPS_PROXY` со значением `http://127.0.0.1:18080`, `OPENAI_BASE_URL=http://127.0.0.1:18080/model/v1` и непригодный для провайдера `OPENAI_API_KEY=profile-proxy-not-a-secret`. Запись Unix-сокета разрешена всем UID; доступ к сети определяется проверкой peer UID. Каталог сокета должен защищать его от подмены.

Оба файла JSON должны быть обычными файлами root с режимом не шире 0600 и находиться в защищённых каталогах. Egress читает их заново при проверке каждого соединения, на котором обслуживается ровно один запрос. Реестр имеет формат `{"version":1,"profiles":{"<uid>":{"userId":"…","profileId":"…","status":"active",…}}}`; остальные поля общей записи, включая `telegramId`, `username`, `home`, `workerSocket`, `homeScope`, `memoryEpoch`, `authorId` и `cubes`, разрешены и здесь не используются. Только статус `active` допускает соединение; неизвестный UID, версия или статус отклоняются. Ответственный за Auth обновляет защищённый реестр. Сам реестр не заменяет проверку действующих прав в Auth.

Для статического API конфигурация имеет вид `{"authorizationSocket":"/run/brai/identity/broker.sock","provider":{"baseUrl":"https://provider.example/v1","apiKey":"…"},"deniedAddresses":["IP хоста",…]}`. Значение ключа доступно только доверенному egress; не помещайте его в аргументы, окружение worker или журналы. В `deniedAddresses` оператор перечисляет публичные адреса хоста и других запрещённых назначений. DNS разрешается egress; все полученные адреса должны быть публичными и не входить в запрет, соединение закрепляется за проверенным адресом. Частные, loopback, link-local, multicast, IPv4-mapped и переходные IPv6-адреса отклоняются. Подключение к публичному серверу не исключает, что тот сам предоставляет дальнейшее проксирование.

Для подписочного Codex `provider` содержит `type: codex-cli`, `sourceSha`, UID/GID доверенного владельца и восемь путей из принятой Root-квитанции `brai_identity_provider_source`: `python`, `sitePackages`, `codex`, `node`, `ownerHome`, `codexHome`, `workerDir`, `componentRoot`. Дополнительно обязательны `providerSourceReceipt: {path, sha256}`, `expectedProviderSourceProducerSha256`, `closedConfig: {path, sha256}`, `helperPath` и `helperSha256`. Установщик сначала проверяет полную квитанцию владельцем источника. Egress повторно сверяет её закрепление, вид и поля путей, Root-владение программами и SHA-256 stdlib helper `componentRoot/services/hermes/extensions/tools/codex_cli_owner.py`. Старый формат `core/runtime/profileHome` отклоняется.

`ownerHome` — новый каталог только для credential DATA; `codexHome` равен `ownerHome/.codex`. Оба принадлежат доверенному UID/GID и имеют режим 0700; родитель `ownerHome` принадлежит Root. До запуска сервиса оператор проверяет завершение старых процессов этого UID и переносит только типизированный auth.json. Namespace сервиса закрепляет оба каталога отдельными bind mounts, а Root `closedConfig` монтирует read-only поверх `.codex/config.toml`. Egress проверяет эти mounts перед resolver; один Root-owned файл внутри изменяемого каталога недостаточен. Конфигурация Codex отключает инструменты, hooks, plugins, MCP и старые настройки; её квалификация и перенос credentials принадлежат оператору.

Перед каждым модельным запросом egress запускает только принятый Root Python с `-I -S -B`, без user site, `.pth`, PYTHONPATH и каталога запуска в import path. Он загружает helper по точному пути и хешу, затем явно задаёт новый HOME/CODEX_HOME, принятый Codex binary и общий flock. Helper не импортирует PM или старый Hermes engine. Окружение содержит только новый HOME/CODEX_HOME, каталог принятого Node и системные `/usr/bin:/bin`; начальный cwd — Root-owned `workerDir`. Штатный resolver проверяет срок действия и при необходимости обновляет credential через Codex CLI. Bearer и account ID живут только в памяти доверенного процесса и направляются на фиксированный публичный `https://chatgpt.com/backend-api/codex/responses`. Таймаут resolver — 20 секунд; отказ закрывает запрос. Этот режим не создаёт статическую копию ключа, не запускает новый вход и не переключает модель.

Worker должен использовать именованный пользовательский provider с `transport: codex_responses`, указывающий на локальный model proxy; фиктивный ключ не является доступом к провайдеру. Обычный `provider: custom` в установленном Hermes для loopback выбирает Chat Completions и не сохраняет нужный протокол. Подписочный маршрут поддерживает только POST `/model/v1/responses`; другие пути явно отклоняются. Поддержка образов и других model API через этот маршрут требует отдельной реализации.

Разрешены HTTP-запросы с абсолютным `http://` URL и CONNECT только на порт 443. CONNECT передаёт двусторонний поток, включая WebSocket поверх TLS. Для статического API модели разрешены POST `/v1/chat/completions`, `/v1/responses`, `/v1/embeddings`, `/v1/images/generations`, `/v1/images/edits` и GET `/v1/models`. В запросе responses значение `store` принудительно равно false; запрос с другим значением отклоняется. Для запросов модели клиентская авторизация удаляется, а доверенный ключ подставляется в Authorization; из клиентских заголовков передаются только Accept и Content-Type. Другие пути модели и методы отклоняются. Прокси не следует перенаправлениям.

Один запрос ограничен заголовками 32 КиБ и телом 8 МиБ. Передача chunked request body, Expect и HTTP Upgrade отклоняется; поддерживается потоковый ответ, включая SSE. У соединений и запросов ограничено время ожидания, передача использует обратное давление, число одновременных соединений ограничено. Ошибка проверки закрывает доступ. До передачи запроса egress проверяет UID и статус в реестре и отправляет доверенному брокеру Auth JSON-RPC 2.0 строкой `{"jsonrpc":"2.0","id":1,"method":"authorize","params":{"uid":123}}`. Брокер отвечает строкой `{"jsonrpc":"2.0","id":1,"result":{"allowed":true}}` или `false`. Только доверенному UID egress разрешено передавать UID проверяемого пользователя; это обеспечивает брокер. Во время потока проверка повторяется каждые 0,4 секунды с таймаутом 0,4 секунды; отказ, ошибка или недоступность брокера закрывают оба конца соединения. При нормальной работе планировщика отзыв действует не позже следующей проверки, включая её таймаут. Обновление реестра отдельно закрывает соединение при следующей проверке.

CLI перед готовностью читает защищённые файлы и проверяет подключение к сокету брокера, затем отправляет `READY=1`, если задан `NOTIFY_SOCKET`. SIGTERM и SIGINT останавливают приём и закрывают активные потоки.

Операторский `publicWebOrigins` может разрешить HTTPS (443) точного публичного домена этой установки на адресе хоста. Это разрешение применяется только к CONNECT браузера: остальные домены и порты сохраняют запрет адресов хоста. Приватные, переходные и смешанные DNS-ответы отклоняются также для разрешённого домена. В DEV настроен только `https://dev.brai.one`; для выдачи кода браузер не требуется.

## Общие изображения и GIF

Личный native image provider использует `/image/images/generations` и `/image/images/edits` локального relay. Egress принимает только форму закреплённого native GPT Image 2 provider; исходные изображения передаются встроенными data URL, произвольные адреса не принимаются. Подписочный credential и account разрешаются существующим доверенным helper и добавляются перед отправкой только в `https://chatgpt.com/backend-api/codex/images/…`. Статический API не служит запасным маршрутом. Общие пределы HTTP и проверка Auth действуют также здесь.

GIF идут отдельным POST `/gif/v1/images/generations`. Допустим только принятый запрос Flare 2.6: GIF, девять кадров по 200 мс, low quality/complexity, один результат. Prompt ограничен 16 КиБ UTF-8. Необязательный root-only `gifProvider.credentialsFile` указывает на защищённый JSON `{"apiKey":"…"}`; файл и каталог недоступны личным процессам. При отсутствии маршрута или недоступном credential запрос отклоняется без смены provider. Подписка диалога и обычных изображений сохраняется.
