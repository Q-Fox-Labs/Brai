# Доверенный identity control

Control проверяет текущую сессию администратора и вызывает Auth `admin-audit` до чтения. Успешный ответ содержит `status`, `body` и `setCookies`; отказ передаётся заголовками `Nats-Service-Error` и `Nats-Service-Error-Code`. Неверный Origin, отсутствующая сессия или неуспешный аудит запрещают чтение. Активный администратор может читать данные профиля в любом известном состоянии реестра: active, blocked, disabled или provisioning. Если данные ещё не созданы, источник возвращает ошибку или пустой список по своему контракту. Cursor подписан и привязан к пользователю, операции, запросу и размеру страницы.

Машинные контракты: [AsyncAPI](asyncapi.yaml), [схемы DTO](schemas/control.schema.json), [приватный OpenRPC](control.openrpc.json).

NATS Services: `brai_hermes_identity`, queue `brai_hermes_identity`, subjects `brai.hermes.identity.v1.admin-memory-list`, `admin-memory-get`, `admin-chats-list`, `admin-chats-get`, `admin-artifacts-list`, `admin-artifacts-get` и `admin-artifacts-download` с тем же префиксом. В запросе нужны `headers: {cookie,origin}` и `userId`. Чтение одной записи принимает `memoryId`, `chatId` или `artifactId`; списки и сообщения принимают `cursor` и `limit` от 1 до 100, по умолчанию 50. Поиск памяти принимает `query`.

Сервис памяти вызывается через закрытый UNIX socket: POST `/admin/list` и `/admin/read`. Полная запись `admin-memory-get` передаётся последовательными частями `{userId,memoryId,snapshotId,offset,totalBytes,sha256,chunkBase64,nextCursor}`: до 450000 исходных байт на часть и 16 МиБ на запись. Каждая часть заново требует активного администратора и записи аудита; cursor связан с сессией, пользователем, записью, профилем и эпохой. Снимок действует до двух минут; одновременно сохраняется не более восьми снимков и 64 МиБ, выполняется не более четырёх чтений полных записей. Web проверяет последовательность, целостность и полный JSON до показа. При отказе, разрыве или истечении срока нужно открыть запись заново. Профиль и UID берутся из root-owned registry, не из запроса. Чаты читаются из копии `state.db` и WAL: исходные файлы открываются без перехода по symlink, владелец и inode проверяются до и после копирования. Путь пользователя не принимается через NATS. Отказ проверки или неподдерживаемая схема возвращает 503. Страницы чатов читаются из защищённой копии SQLite в течение пяти минут; на одну страницу возвращается до 100 записей и 900000 байт текста JSON. Одна запись, превышающая этот предел, даёт 503. Одновременно хранится до 20 копий, для создания сохраняется не менее 512 МиБ свободного места. Страницы артефактов используют offset owner API: при добавлении или удалении объектов между запросами записи могут повториться или пропуститься. Общего ограничения на число сообщений или артефактов нет. Артефакты проверяются по ownerId, внутренний URL не возвращается. `admin-artifacts-download` принимает `artifactId` и возвращает серверу Web descriptor: `artifactId`, `mimeType`, `filename`, `sizeBytes`, `sha256`. Control сверяет владельца, готовность, размер до 2 ГиБ и точный внутренний URL; сам URL и байты не входят в ответ. Web строит адрес из защищённой конфигурации, не передаёт его браузеру и потоково выдаёт байты без redirect, проверяя размер и SHA-256. Несовпадение обнаруживается к концу потока, уже переданные байты отозвать нельзя.

Только доверенный broker запускает `runtime.mjs --stdio` и передаёт строки JSON-RPC 2.0 `{jsonrpc:"2.0",id,method,params}`; ответ содержит `jsonrpc`, `id` и `result` либо `error:{code,message}`. Notifications не получают ответа; batch ограничен 64 запросами. Одновременно выполняется не более 64 запросов. Методы: `identity.resolve`, `identity.invite-redeem`, `identity.revalidate`, `authorize`, `tools.list`, `tools.call`, `login.send`. Broker получает UID через SO_PEERCRED и не принимает его от worker. `login.send` допускается только для текущего проверенного личного события Telegram. Код отправляется напрямую через Bot API и не возвращается worker; неизвестный исход не означает разрешение на повтор.

Зарезервированное значение `userId: "__quarantine__"` обозначает архив до разделения и допускается только в перечисленных административных операциях чтения. Оно не является пользователем и не даёт сессию, вход или доступ к инструментам. До чтения Auth проверяет активного администратора и записывает аудит с этим идентификатором. При отсутствующей или неверной конфигурации control возвращает 503. Обычный профиль в UID-реестре для архива не создаётся.

В защищённом конфиге `quarantineProfile` содержит `userId`, `profileId`, `homeScope`, `memoryEpoch`, `cubes`, `home`, `workerUid` и необязательный `authorId`. Для памяти используется `userId` этого профиля и отдельная конфигурация карантина memory gateway, для чатов — `home` и `workerUid`. `quarantineArtifactsOwnerId`, если задан, определяет владельца архивных артефактов; иначе используется `quarantineProfile.userId`. Эти значения не принимаются из пользовательских запросов. Memory gateway обязан проверять признак карантина и заданную область; если его поддержка или миграция ещё не установлена, наличие конфига control не подтверждает доступность данных.

Путь `BRAI_IDENTITY_CONTROL_CONFIG` указывает на root-owned JSON mode 0600. Настройки: `origin`, `cursorKey` не короче 32 байт, `registryPath`, `memorySocket`, `telegramToken`, `artifactsInternalBaseURL` и `nats` с `servers` и необязательными `user`, `password`, `credsFile`, `caFile`. Реестр также должен быть root-owned mode 0600; его родительские каталоги не должны разрешать запись группе или другим пользователям.

Сборка `startControl(config, adapters)` принимает `perUserRuntime`, `historyCall`, необязательный `onIdentityChanged` и доверенный порт `telegramSend`. Последний предназначен для изолированной проверки доставки; при отсутствии порта используется прямой Telegram Bot API. `perUserRuntime(profile)` возвращает объект с `listTools()` и `callTool(name,args,signal)`. `historyCall(profile,name,args,signal)` выполняет отдельное проверенное чтение истории; owner берётся из `profile`. `runStdio(adapters)` принимает те же порты. Без них инструменты недоступны. `tools.list` возвращает `{tools:[{name,description,inputSchema}]}` после проверки UID и роли. Интеграцию с реальными Auth, NATS, Telegram, memory gateway и личным runtime нужно проверять до включения; модуль сам не настраивает системные разрешения или ACL.

`identity.revalidate` повторно читает реестр и Auth. При неактивной записи или изменении ранее подтверждённой роли вызывается `onIdentityChanged({userId,profileId,status,role})`. Broker сам запускает периодические проверки и при недоступности Auth, отсутствии записи или отрицательном результате останавливает worker и egress. Отзыв только web-сессий не меняет результат `telegram-resolve`; для немедленной остановки по этому событию требуется отдельный подтверждённый сигнал Auth.

`runtime.mjs --stdio` собирает персональные инструменты для broker. Root-owned `runtimeProfilesPath` читается перед каждым вызовом и содержит объект по UID с `{userId,profileId,home,toolsConfigPath,stagingRoot,cacheRoot}`. UID, userId, profileId и home сверяются с registry и Auth. Staging заканчивается UID; staging и cache принадлежат root, не допускают запись группы или остальных и не пересекаются с домашними областями. Cache равен publisher `resultRoot` данного владельца. Broker копирует готовые файлы в home и не раскрывает worker root-пути.

`toolsConfigPath` и publisher JSON принадлежат root и имеют mode 0600. `ownerId` обоих совпадает с userId, `allowedReadRoots` publisher содержит только staging данного UID. Рядом расположен защищённый `files.json` с ownerId пользователя: `stateRoot=<home>/workspace/files`, `resultRoot=<home>/results`, `readRoots` — ровно `<home>/workspace`, `<home>/media`, `<home>/results`. Изменение защищённых конфигураций закрывает старые подключения при следующем вызове.

Дополнительные private методы broker: `identity.profile-ready`, `files.configuration/get/list/prepare` и `artifacts.publish/fetch`. Publisher вызывается только broker после проверки UID и создания root snapshot; прямые `publish_file/fetch_file` worker не доступны. Для неподтверждённых owner bearer `gameCore`, `history` MCP и `transcription` должны быть ровно `{ "enabled": false }`; включение без проверки привязки завершает сборку отказом. `history_list/get` используют NATS web/RLS с userId из проверенного профиля. Нужна сквозная приёмка Auth, broker, owner API и NATS ACL.

Внешние `serviceRoots` ограничены тремя read-only путями worker: `/opt/brai-profile/engine`, `/opt/brai-profile/runtime`, `/opt/brai-profile/instructions`. Они разрешают внутреннее чтение, не публикацию или временные файлы. Личные инструкции остаются внутри собственного HOME.
