# Agent

Отдельная программа соединяет web через NATS с существующим Codex app server. История и выполнение принадлежат Codex; своей БД и очереди заданий нет.

## Запуск

Из корня: `npm ci`, `npm run build:agent`, затем `BRAI_AGENT_CONFIG=/absolute/config.json npm start --workspace=@brai/agent`. Конфигурация содержит `codex.socketUrl`, `nats.servers`, настроенные `projects` с `projectId/name/cwd`, необязательные `allowedModels` и `newThread.model/approvalsReviewer`. Credentials задаются явно в защищённой конфигурации. Сборка и запуск не читают admin. Health: `BRAI_AGENT_CONFIG=/absolute/config.json npm run health --workspace=@brai/agent`.

## Контракт

NATS Services `brai_agent`, версия2.0.0, endpoint `brai.agent.v2.rpc`. Запросы описаны в [AsyncAPI](asyncapi.json) и [JSON Schema](schemas/messages.schema.json). Действия: `projects`, `status`, `threads`, `create`, `open`, `turns`, `items`, `activities`, `item`, `start`, `steer`, `interrupt`, `answer`, `archive`. Ответ успешной мутации содержит `outcome=accepted` и исходный `operationId`. Ошибки используют стандартные NATS Service Error headers; `outcome` различает `not-sent`, `unknown`, `query`. Неизвестный исход нельзя автоматически повторять. `archive` требует projectId, threadId, generation и operationId, проверяет native cwd и вызывает thread/archive без resume; accepted подтверждает архивацию, после которой локальная проекция удаляется. Native ошибка, включая наблюдавшийся -32600 с возможным эффектом, не считается успехом.

`status` немедленно возвращает `limits` из памяти. Его форма `AgentLimits`: состояние `loading|ready|stale|unavailable`, возрастающий в поколении `revision`, Unix milliseconds последнего полного чтения `observedAt` или `null` и до двух реальных окон `primary|secondary` с `remainingPercent` (0–100), `windowDurationMins` и `resetsAt` (Unix seconds), последние два nullable. `validateLimits` проверяет закрытую форму для потребителей `@brai/agent/contracts`. Первое чтение выполняется после соединения и готовой авторизации; полная сверка повторяется раз в 60 секунд, нативное обновление запускает сверку раньше. Уведомление частичное, поэтому его поля не объединяются в клиентскую квоту. Одновременно идёт максимум одно чтение и хранится максимум один ожидающий запрос; новые чтения стартуют не чаще раза в 5 секунд. После ошибки прежние данные становятся `stale`, а без доступного окна лимит `unavailable`. Ответ старого соединения или аккаунта отбрасывается; данные аккаунта, тарифа и reset credits не входят в проекцию. Ошибки чтения лимита не меняют готовность чата.

`generation` защищает мутации от старого исполнителя. Одинаковый operationId возвращает исходный результат; другое содержимое отклоняется. Ledger ограничен и живёт только в текущем поколении. Разрешены только настроенные проекты и модели; произвольного RPC proxy нет. Мутация не ждёт завершения хода.

Core NATS `brai.agent.v2.event` передаёт только AG-UI `STATE_SNAPSHOT`: полное ограниченное представление сообщений, предложенных планов, идентификаторов действий и ожидающих запросов, с project/thread/generation/epoch/seq. Внутри того же generation/epoch любой больший seq заменяет состояние целиком: промежуточные снимки можно объединять. После нового поколения/epoch читают `open`; Brai не повторяет turn/start. Native Codex самостоятельно продолжает активную цель. Сохранённую историю читают native `turns/items`, передавая непрозрачный cursor.

Четыре формы: команда, изменение файлов, дополнительные разрешения, вопрос. Ответ проверяется исходной native schema до first-wins claim; stale/неизвестные запросы не подтверждаются. Для вопроса `answer.answers` содержит ровно исходные ID: `{answers: [value]}` передаёт ответ, `{answers: []}` — явный пропуск. Непустые ответы не могут состоять из пробелов; при наличии вариантов и `isOther=false` принимаются только исходные label, с `isOther=true` или без вариантов разрешён собственный текст. Отсутствующий ID не означает пропуск и отклоняется. В событиях raw reasoning, binary/media и секреты профиля не передаются. Отдельное чтение item может вернуть изображения сообщения. Публичная краткая reasoning summary доступна только в раскрытом действии. `phase`, статус и код выхода сохраняются; сокращение обозначается явно.

Размеры и ёмкости экспортированы из `@brai/agent/contracts`. При переполнении интерфейс получает отказ либо восстановление снимка. Brai не выбирает замену модели; для созданных им чатов provider fallback отключён. Для прежних чатов настройкой fallback владеет Codex. Остановка agent закрывает его подключения; Codex daemon остаётся владельцем собственного выполнения.

Отклонённые server request получают RPC-ошибку с отдельной причиной и не входят в ожидание ответа пользователя. Снимок сохраняет из ошибки завершённого хода только ограниченные поля message и код codexErrorInfo; additionalDetails и misalignment не передаются.

Для неподдерживаемого `item/tool/call` уведомление сохраняет в `PendingRequest.params` только optional `tool` и `namespace`: идентификаторы из 1–64 ASCII букв, цифр, `_` и `-`. Аргументы, результаты и прочие поля не передаются. Пустые params прежних уведомлений остаются допустимыми. Namespace `codex_app` обозначает инструменты приложения Codex, а не сервис проекта. Отправленный Brai отказ подтверждает только ответ этого клиента: при нескольких клиентах native сервер принимает первый ответ или ошибку; окончательный результат выполнения принадлежит Codex.

## Проверки

`npm run typecheck:agent`, `npm run test:agent`, `npm run build:agent`. Unit проверки не используют аккаунт, сервер Codex или модель. Upstream wire schemas закреплены в [contracts/codex](contracts/codex/README.md); обновление требует проверки фактического протокола, а не собственного форка.

`models` возвращает до100 видимых native моделей, их `efforts/defaultEffort`, названия и configured `defaultModel`; configured `allowedModels` ограничивает каталог и исполнение. Результат кэшируется только в поколении Codex. `create` принимает optional `model`; `start` — optional `model/effort`. Явный выбор проверяется по каталогу до native мутации. Значения передаются напрямую в thread/start и turn/start и становятся штатными default для следующих ходов. Steer не меняет настройки. Snapshot thread metadata может содержать `reasoningEffort` и фактический model из resume/принятого start. Наличие в каталоге само по себе не подтверждает доступ к inference.

`create/start.permissionMode` — `ask|auto|full`, default `auto`. Native mapping: ask = on-request/user/workspace-write; auto = on-request/auto_review/workspace-write; full = never/user/danger-full-access. Для turn/start workspaceWrite ограничен configured cwd, networkAccess=false. Профиль применяется только к новому заданию, без изменения global config.toml. Pending approvals проходят native reviewer; браузер не отвечает автоматически. Произвольные permission/sandbox поля не допускаются.

`start/steer.images` — optional массив от 1 до 8 закрытых data URLs PNG/JPEG/WebP со строгим canonical base64. Удалённые URL, пути, SVG, пробелы в base64 и ненулевые pad bits запрещены. `text` содержит до 65536 символов; его можно опустить или оставить пустым при изображениях. Без изображений нужен текст с непробельным символом. JSON команда занимает до 983040 bytes (960 КиБ); все изображения вместе — до 655360 decoded bytes (640 КиБ). Schema и `validateCommand` проверяют структуру; сервер отдельно проверяет decoded budget и MIME signature до native мутации. Отказ даёт `INVALID_ARGUMENT/not-sent`.

`models` передаёт `inputModalities` из native каталога; отсутствие поля использует закреплённый native default `["text","image"]`. `imageLimit` равен пределу Brai 8 при поддержке image, иначе 0. Это предел приложения: каталог не задаёт числового предела конкретной модели. Start проверяет выбранную модель, steer — модель активного хода. Отсутствующая в каталоге модель и text-only модель отклоняют изображения с `UNSUPPORTED/not-sent`, без подбора замены. Image-only команда передаёт native `{type:"image",url:...}` без пустого text input.

Operation ledger хранит SHA-256 полной canonical команды и результат, без исходных data URLs. Совпавший operation ID и содержимое возвращают прежний результат; изменение любого изображения под тем же ID даёт конфликт. Native history остаётся у Codex. Компактный display, snapshot и публичная история содержат только `imageCount` для userMessage (считает native image/localImage) и текст, без image URL/path/bytes.

Исходящий native кадр и send buffer ограничены 2 MiB; входящий кадр — 16 MiB. Чтение native items использует страницы до 10 элементов: `open` загружает последнюю страницу; `items` собирает до десяти сообщений пользователя/агента вместе с действиями между ними и возвращает native cursor без пропусков. Действия не расходуют число сообщений. Последняя страница может содержать меньше сообщений; защитный предел одного ответа — 1000 записей. Каждая native страница сразу преобразуется в display без накопления raw media. Это позволяет прочитать десять сообщений с максимальными вложениями Brai и сразу отбросить binary после display проекции. Внешние state/frame limits не увеличены. Произвольные импортированные native media или ответы больше 16 MiB не поддерживаются; превышение закрывает соединение и требует восстановления состояния. Проверка локальным WebSocket mock не использует аккаунт или inference; при запрете Unix sockets средой этот тест пропускается.

## Ленивое чтение действий и активность

`open`, `items` и события передают текст сообщений пользователя/агента и native предложенных планов. Остальные записи содержат только `id/turnId/type/text:""`, optional `status/exitCode/revision`; command, output, diff и summary отсутствуют. Для reasoning поле `hasContent` сообщает наличие непустого публичного текста; false позволяет скрыть запись и пустую группу до раскрытия. Browser не получает тела скрытых действий. Native history содержит тела, поэтому backend читает их у Codex, но не отправляет до раскрытия.

`activities` принимает `projectId/threadId/turnId/itemIds`: от 1 до 100 уникальных IDs. Ответ `{generation,data:DisplayItem[]}` сохраняет порядок запроса и содержит заголовки `summary` до 256 UTF-8 bytes, пустой text и состояние. Для reasoning без публичного текста заголовок пустой; клиент скрывает такую запись. Непустое reasoning раскрывается через `item` с публичным текстом. `item` принимает `projectId/threadId/turnId/itemId`; ответ `{generation,item:DisplayItem}` содержит display body. Чтения не запускают ход; generation фиксируется до чтения, смена поколения даёт `STALE_GENERATION` с outcome query. Не найденный item/turn даёт `NOT_FOUND`. Повтор чтения безопасен. Для старых действий используется native exclusive anchor: predecessor затем ascending page; live cache ограничен 128 отображёнными элементами на session и существующими пределами display полей. Raw reasoning и медиа действий не возвращаются; изображения userMessage доступны через item. Поля действий сокращаются с явным маркером. Для сообщений `item` возвращает текст без потерь частями до8192 UTF-16 единиц, optional `nextCursor` (null в конце); продолжение передаётся в optional `cursor`. Курсор связывает SHA-256 полного текста со смещением; изменение текста или неверный курсор даёт `STALE_ITEM`, outcome query. Чтение не запускает ход. История и снимки остаются компактными; web автоматически собирает все части для userMessage/agentMessage, показывает состояние загрузки и повтор ошибки. Совместный выпуск web/agent обязателен: прежний web не собирает продолжение, прежний agent не выдаёт полный текст.

`revision` — seq изменения live item; для сохранённого item без live версии — 0. Изменение вывода обновляет revision, сохраняя скрытое представление. `timestamp` сообщений и `thread.lastMessageAt` используют Unix milliseconds; native `updatedAt` остаётся Unix seconds. Native startedAtMs, затем completedAtMs определяют время сообщения; для старых записей без времени fallback — updatedAt*1000. Live сообщение фиксирует время первого наблюдения, delta/command/plan его не меняют. `thread.active` отражает native active, ход inProgress или подтверждённую активную цель между ходами; потеря соединения выключает live индикатор.

`threads` запрашивает native updated_at desc, затем сортирует страницу по времени сообщения и ID. Для определения времени проверяет до десяти native страниц по 10 items на чат, параллельно не более четырёх чатов; результаты кэшируются по native updatedAt, до 1000 чатов на generation. Если сообщения нет в этом ограниченном окне, lastMessageAt=0. Native continuation cursor сохраняется: порядок всех загруженных страниц уточняет потребитель. Авторизация и доступ проектов остаются на существующей web/NATS границе; новые чтения не обходят проверку configured cwd.
После принятого задания чата без имени agent независимо формирует смысловое название одним коротким запросом gpt-6-luna (effort=low). Это работает и после повторного открытия чата: название строится по native preview первого задания, если он непустой, иначе по принятому заданию. Временный native чат имеет ephemeral=true, отключённый fallback и не сохраняется в истории. Основное задание не ждёт названия. Схема ответа ограничивает название 60 символами; более длинный ответ сокращается по границе слова без повторного запроса. Результат сохраняется штатным thread/name/set; thread/name/updated обновляет sidebar и заголовок через существующий поток. Уже заданное или изменённое вручную название сохраняется. Повтор команды не вызывает генерацию; сохранённое имя исключает новые запросы. Ошибка названия не останавливает рабочее задание и не повторяет платный запрос автоматически. Временный native отказ `thread/read` с кодом -32603 допускает до десяти чтений с паузой 250 мс; готовое название сохраняется между ними, inference и мутации не повторяются. Другие ошибки и смена поколения прекращают попытку. Диагностика различает начальное чтение и проверку текущего имени перед сохранением. Следующее принятое задание чата без имени допускает одну новую попытку по исходному поручению, в том числе после повторного открытия. Одновременно выполняется не более одной генерации для чата. Ошибка записывается с этапом, локальным и native кодами, без текста задания или ответа. Если Luna отсутствует в разрешённых моделях, генерация пропускается.

Генератор названия получает одну инструкцию до150символов и не более2048символов первого задания, без истории основного чата. Native model/list подтверждает low как минимальный effort Luna. В request-local настройках выключены инструкции навыков, приложений, среды, разрешений и режима сотрудничества, плагины, агенты и вспомогательные инструменты; разрешения остаются read-only/never. Config/read используется только внутри исполнителя, без передачи значений конфигурации в модель: каждый унаследованный MCP явно выключается по имени. Глобальные инструкции хоста, которые публичный API не позволяет отключить, сохраняются; глобальный профиль Codex не меняется.

`item` для userMessage дополнительно возвращает optional `images`: до 8 закрытых PNG/JPEG/WebP data URLs, до 640 КиБ decoded суммарно и в пределах входного бюджета команды. Поле отсутствует при неподдерживаемом или слишком большом наборе; `imageCount` сохраняется. Удалённые URL и localImage пути не передаются. Чтение использует native историю с прежней проверкой проекта, чата и поколения; не запускает ход. Web автоматически читает вложения сообщений через общий ограниченный кеш detail и показывает миниатюры; ошибку можно повторить.

Начало хода в свободном чате не ограничивается числом ходов в других чатах: native Codex определяет возможность исполнения. Локальные пределы сохраняются: до16 проекций чатов, до64 одновременных запросов, ограниченные очереди и размеры кадров.


`thread.finalMessageId` — ID последнего сообщения, если это agentMessage с phase=final_answer, иначе null. `thread.awaitingReply` показывает неотвеченный native запрос (включая разрешения), либо вопрос в итоговом сообщении при завершённом ходе. Текстовый вопрос определяется знаком `?` или `？` вне блоков и фрагментов кода и адресов ссылок; вопрос в видимой подписи ссылки сохраняется. Последующее сообщение пользователя снимает его. Служебные действия не снимают итог. Поля optional для совместимости; список и live снимки передают одинаковую проекцию.


## Режимы и материалы

`start.agentMode` принимает `default|plan|goal`; отсутствие поля означает `default`. Обычный и плановый ход передают явный native `collaborationMode`: режим, выбранную модель и effort внутри `settings`, а `developer_instructions:null` выбирает встроенные инструкции Codex. Это снимает предыдущий plan mode. При активной цели явное ordinary/plan задание сначала ставит цель на паузу, затем начинает свой ход; цель остаётся в панели. Steer режим не меняет.

В режиме `goal` текст задания становится objective, изображения запрещены до любого эффекта. Необязательный `tokenBudget` — положительное безопасное целое; Brai не назначает бюджет по умолчанию. Новое задание цели удаляет прежнюю цель, задаёт native default/model/effort/permissions через `thread/settings/update`, затем вызывает `thread/goal/set` с active. Удаление исключает наследование прежнего бюджета и счётчиков. Native set самостоятельно запускает продолжение; Brai не вызывает второй turn/start и не исполняет собственный цикл. Модель и effort проверяются по разрешённому каталогу. Название нового чата формируется тем же независимым генератором, что и для обычного задания.

`goalGet` — чтение по project/thread, возвращает `{generation,goal:GoalProjection}`. `goalSet` и `goalClear` — закрытые мутации с generation/operationId. Set принимает хотя бы одно поле: непустой `objective` до 65536 символов, `status:active|paused`, `tokenBudget` положительное безопасное целое или null для удаления явного бюджета. Без status сохраняется текущий статус, для новой цели используется native active. Возобновление сохраняет счётчики и бюджет, снимает plan mode через native settings/default и проверяет модель/effort до эффекта. Pause и clear сначала меняют цель, затем interrupt подтверждённого активного хода: native pause/clear сами по себе текущий ход не прерывают. Ответ мутации имеет прежнюю форму accepted и дополнительную `goal`.

Успешный первый этап многоэтапной мутации не откатывается. Ошибка следующего этапа даёт `outcome:unknown`, даже если следующий вызов не отправлен; повтор operationId возвращает прежний результат без нового эффекта. Клиент восстанавливает цель и ход чтением `open/goalGet`, затем может выполнить отдельное действие по новому состоянию. Смена generation запрещает новые этапы. Проекции активных целей и выполняемые мутации не вытесняются при admission другого чата.

Snapshot содержит `goal:GoalProjection` и `planProgress:PlanProgress`; оба поля optional в публичном контракте для совместимости с прежними снимками, новый owner выдаёт их всегда. Цель имеет state ready/stale/unavailable и nullable value с native статусом active/paused/blocked/usageLimited/budgetLimited/complete, objective, tokensUsed, timeUsedSeconds, tokenBudget, createdAt/updatedAt. Время цели — секунды, даты — Unix seconds. Обрыв или ошибка чтения сохраняет прежнюю цель как stale; отсутствие доступных данных обозначается unavailable. Native уведомление, опередившее ответ чтения, имеет приоритет. Open/reconnect читает сохранённую цель через native goal/get; raw профиль не попадает в проекцию. Objective в снимке ограничен 16 КиБ, сокращение явно отмечено `truncated`.

Предложенный документ — только native item type `plan`, отдельный от шагов выполнения. Его текст сохраняется в snapshot/history до 32 КиБ и 48 КиБ сериализованного JSON; больший документ получает `truncated:true`. Started/delta дают display status inProgress; item/completed заменяет накопленные дельты окончательным native текстом и даёт completed. История подтверждает completed по native completedAtMs либо завершённому соответствующему ходу. Текст из delta не считается окончательным документом. Страницы истории ограничиваются оставшимся бюджетом ответа, native cursor сохраняет продолжение без пропусков. Закрытый клиентский материал не требует нового lifecycle на стороне сервиса.

`turn/plan/updated` обновляет отдельный `planProgress`: turnId, nullable explanation, до 100 шагов step/status (pending/inProgress/completed), state live/stale/unavailable и флаг truncated. Native история не предоставляет восстановление этих шагов. После reconnect прежний список остаётся stale; при холодном открытии он unavailable. Новый ход сбрасывает старый прогресс. Прогресс не создаёт синтетический plan item и не выдаётся за сохранённый документ.

Изменение расширяет существующую закрытую границу без новых subjects. Web и agent обновляются согласованно; после обновления клиент перечитывает снимок. Старый потребитель закрытой JSON Schema может отвергнуть новые поля.


Snapshot содержит optional `contextUsage:{usedTokens,contextWindow}|null`: `usedTokens` — `last.totalTokens` из `thread/tokenUsage/updated`, включая вход и ответ последнего запроса, а не накопленный `total`. `contextWindow` — положительный native `modelContextWindow` или null при неизвестном лимите. До первого события поле отсутствует; после потери соединения сбрасывается в null и ждёт нового события. Счётчик может уменьшаться после компактизации. Данные принадлежат выбранному thread и не оцениваются по тексту истории.
