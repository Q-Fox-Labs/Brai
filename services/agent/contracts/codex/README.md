# Граница Codex app-server

Контракт фиксирует используемое подмножество app-server 0.159.2 по наблюдению на raw WebSocket. После `initialize` клиент отправляет уведомление `initialized` с `{method:"initialized",params:{}}` без RPC ID. Параметры методов передаются полями верхнего уровня по именам; описание OpenRPC использует `paramStructure: "by-name"`, а `x-paramsSchema` ссылается на целую upstream-схему параметров.

Пакеты на проводе имеют формы `{id,method,params}`, `{id,result}` или `{id,error}`, а уведомления — `{method,params}`. Поле `jsonrpc: "2.0"` не требуется фактическим протоколом; OpenRPC здесь описывает вызовы, но не меняет wire-протокол.

Поддерживаемые вызовы перечислены в `openrpc.json`: initialize; чтение, перечисление, продолжение, архивирование и отписка от треда; чтение страниц turns/items; start, steer и interrupt хода. `thread/read` до первого хода может вернуть `-32600`; paged turns/items работали после первого хода. Ошибка `-32600` при `thread/archive` наблюдалась вместе с применённым эффектом, поэтому до сверки состояние неизвестно.

Управляющие вызовы меняют состояние. После тайм-аута или разрыва исход изменения неизвестен, автоматический повтор запрещён. Совпадающий `id` связывает ответ с запросом, но не означает отмену или идемпотентность. `turn/steer` использует тот же turn ID; устаревший expectedTurnId отвергнут. `turn/interrupt` для подтверждённого активного хода вернул пустой результат и уведомление `turn/completed` со статусом `interrupted`; немедленный вызов после старта может попасть в гонку и получить `-32600`.

Серверные запросы `item/commandExecution/requestApproval` доставлялись обоим клиентам; отказ завершал запрос у обоих. Экспериментальный `item/tool/requestUserInput` в plan mode пережил отключение всех тестовых клиентов на 6 секунд: после reconnect тот же pending RPC ID был доставлен снова, точные ответы завершили ход. Протокол ответа не содержит подтверждения доставки; повторный ответ и exactly-once не доказаны. Схема `item/permissions/requestApproval` включена для трассировки upstream типов, но live-сценарий не проверен. Ответ с `permissions` и `scope` описывает профиль прав, а не решение allow/deny.

В `manifest.json` перечислены точные upstream-файлы и SHA-256. `schema.json` — Draft-07 замыкание используемых upstream типов. При компиляции upstream-схем Ajv отключает проверку именованных `format`: upstream использует `uint64` и аналогичные форматы, которым здесь не назначаются неподтверждённые валидаторы; ограничения `type`, `minimum` и остальные ключевые слова сохраняются. Пересборка: `node services/agent/scripts/build-codex-contract.mjs --source-directory <каталог схем 0.159.2>`. Не подменяйте источник CLI 0.157.1. OpenRPC отдельно перечисляет schema-only уведомления command execution output delta, file change output delta и turn plan, а также запрос `item/fileChange/requestApproval`; их упоминание не подтверждает live-поддержку. В выгрузке 0.159.2 нет отдельного определения с именем AvailableCollabItems.

Числа в `x-probeLimits` — только пределы тестовых прогонов операции 1: RPC 12 секунд, история 10 страниц по 20 элементов, кадр 2 MiB, прогон 240 секунд и очистка 60 секунд. Это не обещания продукта. Ожидание pending question проверено только на 6 секунд; восстановление после перезапуска daemon, перегрузка, stdout delta и file-change/permissions flows не проверялись.
