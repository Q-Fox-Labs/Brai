# Публикация файлов агента

Программа `dist/publisher-mcp.js` предоставляет MCP stdio инструменты `publish_file` и `fetch_file`. Она публикует самостоятельные файлы для пользователя и творческие кандидаты. Рабочие исходники, логи и служебные материалы не относятся к этим инструментам. Результаты встроенной генерации Codex сохраняют свой native формат.

Publisher обращается только к [публичному контракту artifacts](../artifacts/CONTRACT.md): metadata через NATS Services, байты через HTTP. Доступ к БД, каталогам artifacts и внешним share-ссылкам не нужен. Схемы MCP аргументов находятся рядом с обработчиками в `src/publisher-mcp.ts`; payload NATS проверяется схемами владельца artifacts.

## Запуск и доверенная конфигурация

С готовыми workspace зависимостями выполните `npm run build --workspace=@brai/agent`. Затем запустите `node services/agent/dist/publisher-mcp.js` с `BRAI_AGENT_PUBLISHER_CONFIG`, указывающим абсолютный путь к защищённому JSON, и `BRAI_AGENT_OWNER_ID`. Последняя переменная задаёт проверенного владельца и должна точно совпадать с `ownerId` JSON. Владелец — непрозрачный ID длиной 1–128 символов без пробельных символов. Модель не может передать или заменить владельца.

```json
{
  "ownerId": "canonical-owner",
  "resultRoot": "/absolute/agent-results",
  "allowedReadRoots": ["/absolute/user-output"],
  "artifacts": {
    "baseUrl": "http://artifact-files.internal",
    "uploadBaseUrl": "https://artifact-upload.example",
    "nats": {
      "servers": ["nats://broker.internal:4222"],
      "inboxPrefix": "_INBOX.brai_agent_publisher"
    },
    "timeoutMs": 10000
  },
  "uploadTimeoutMs": 1800000
}
```

`nats.user` и `nats.password` необязательны; реальные значения хранит защищённая конфигурация экземпляра. `baseUrl` задаёт доверенный внутренний адрес выдачи. `uploadBaseUrl` задаёт доверенный адрес загрузки, по умолчанию равен `baseUrl`. У адресов допустим общий prefix пути; credentials, query и fragment запрещены. Ответ artifacts не может перенаправить publisher на другой origin или путь. Redirect запрещён.

`resultRoot` должен быть каноническим абсолютным путём без symlink, `..`, двойных разделителей и завершающего разделителя. Он совпадает с `artifacts.resultRoot` основного Agent. Разрешённые корни чтения нормализуются через realpath. Конфигурация и имена результирующих файлов не допускают символы `?`, `#`, `%`, обратную косую черту, угловые скобки и управляющие символы: ссылки на такие пути неоднозначны для Markdown и Agent. Обычный Unicode и пробелы поддерживаются. Имя файла ограничено 255 байтами.

`timeoutMs` — срок NATS запроса, по умолчанию и максимум 10000 ms. `uploadTimeoutMs` — срок всей операции, включая snapshot, HTTP и проверку, по умолчанию и максимум 1800000 ms. Клиент MCP должен разрешать ожидание до этого срока; более короткий timeout клиента может отменить операцию раньше. HTTP адаптер использует Node.js http/https с обратным давлением и без отдельного срока ожидания headers; общий AbortSignal управляет передачей и остановкой. Stdio stdout содержит только MCP; диагностика startup безопасно выводится в stderr.

## Операции

`publish_file` принимает `{path,requestId,title?}`. `path` — абсолютный путь к обычному файлу в разрешённом read root. Symlink наружу и подмена промежуточного каталога при открытии закрыты realpath проверками; на Linux дополнительно проверяется путь открытого файлового дескриптора. Сначала publisher потоково создаёт snapshot, считает размер и SHA-256. Затем он вызывает `prepare` с `kind: original`, `source: agent` и `details.agentPublisher: {version:1,sha256,sizeBytes}`.

Устойчивый request key включает hash владельца и пользовательского `requestId`; содержимое входит в параметры `prepare`. Точный повтор после перезапуска возвращает прежний артефакт. Изменённые байты или metadata при прежнем ключе дают `OPERATION_CONFLICT`; новая версия требует нового ключа. Перед каждым PUT выполняется `get`. При потере подтверждения PUT publisher читает `get` и признаёт успех только для ready с ожидаемыми размером и SHA-256. Он не повторяет байты внутри потерявшего подтверждение вызова. Следующий вызов с тем же ключом снова проверяет состояние до передачи.

`fetch_file` принимает `{artifactId}`. Он читает metadata, проверяет фиксированного владельца и ready, затем использует существующую проверенную локальную копию или потоково восстанавливает её по `internalUrl`. Размер и SHA-256 скачанного файла обязаны совпасть с metadata. Путь назначения и владелец в аргументах запрещены.

Обе операции возвращают `{artifactId,filename,mimeType,sizeBytes,sha256,localPath,markdown}` только после подтверждения ready. Локальная копия имеет путь `<resultRoot>/<artifactId>/<filename>`; publisher создаёт её без перезаписи и устанавливает права `0444`. Существующий другой файл даёт конфликт, а не замену. Отдельные UUID не дают права читать чужие артефакты.

`markdown` содержит обычный абсолютный путь в угловых скобках. PNG, JPEG, WEBP, GIF, MP4 и WEBM с проверенной сигнатурой получают синтаксис `![имя](<путь>)`; остальные файлы получают `[имя](<путь>)`. SVG и HTML всегда остаются файлами. MIME изображения или видео определяется ограниченным prefix байтов. Сигнатура позволяет выбрать безопасный способ представления; она не доказывает полную корректность media container. Дальнейшая выдача и доступ принадлежат Agent/Web и artifacts.

## Пределы, отмена и ошибки

Точный предел файла — 2147483648 байт (2 GiB), включая пустой файл как допустимый случай. Publisher допускает две операции одновременно; третий вызов получает `OVERLOADED`, очереди нет. File/HTTP buffers ограничены 65536 байтами, prefix — 512 байтами. Файл целиком в память не загружается. Snapshot и окончательная копия могут временно занимать по одному размеру файла на диске.

MCP отмена, timeout, SIGINT/SIGTERM и закрытие stdio прекращают чтение/HTTP. Все временные snapshot текущих операций удаляются. Если snapshot уже установлен, проверенная окончательная копия остаётся для безопасного повтора; отмена не удаляет готовые удалённые артефакты. После аварийного завершения процесса временный `.pending-*` может остаться. Уборка таких файлов требует проверки, что их больше не использует другой publisher; автоматической общей очистки нет.

Ожидаемые ошибки: `INVALID_ARGUMENT`, `READ_ROOT_DENIED`, `INVALID_FILE`, `INVALID_FILENAME`, `FILE_TOO_LARGE`, `FORBIDDEN`, `NOT_READY`, `HASH_MISMATCH`, `LOCAL_CONTENT_CONFLICT`, `UNSAFE_RESULT_PATH`, `OPERATION_CONFLICT`, `NOT_FOUND`, `OVERLOADED`, `CANCELLED`, `TIMEOUT`, `ARTIFACTS_UNAVAILABLE`. Неожиданные ошибки в MCP сводятся к `PUBLISHER_UNAVAILABLE`; credentials, bearer URL и содержимое файла в ошибках не возвращаются.

## Проверка

`node services/agent/tests/publisher.test.mjs` проверяет реальные временные каталоги, durable prepare повторы, restart, changed bytes conflict, потерю PUT ACK, restore/hash mismatch, read/destination symlink, oversized sparse file, безопасный Markdown, MCP SDK, NATS headers и отмену. Локальный HTTP test проверяет настоящий PUT/GET, потерю ready ACK, медленный PUT и прерывание stalled GET. В среде без разрешения loopback listen HTTP сценарии явно отмечаются skipped; нужен разрешённый локальный запуск для полной проверки.

Тест потока обрабатывает ровно 2 GiB и отдельно 2 GiB + 1, используя повторяемый 65536-byte chunk. Он измеряет RSS и external memory каждые 16 MiB и проверяет рост менее 128 MiB. Это подтверждает предел и память преобразования; настоящий 2 GiB HTTP upload относится к интеграционной приёмке artifacts и конфигурации экземпляра.
