# Контакты

Самостоятельный service_contacts: одна Telegram-идентичность на владельца
независимо от бота/sourceId/чата/темы. Имя и username не служат ключом.

[Контракт](CONTRACT.md), [AsyncAPI](asyncapi.yaml),
[общие DTO](schemas/common.schema.json), [операции](schemas/api.schema.json),
[запуск и поставка](DEPLOYMENT.md).
Одна программа main соединяет ядро, PostgreSQL и NATS Services.
Миграция запускается отдельно owner-ролью. Temporal worker, очередь повторов,
ИИ, файлы и Telegram API внутри сервиса отсутствуют.

Три таблицы схемы contacts: contacts, contact_identities, contact_operations.
Актуальный профиль обновляется по происхождению каждого поля; результат resolve
и снимок поступления неизменяемы. Факты Истории сохраняются с квитанцией,
доставляет их вызывающий долговечный сценарий.

Приём использует узкий запрос по схемам владельца, сохраняет запрос и результат.
Пустые строки не очищают профиль, недоступное фото не блокирует сообщение.
Аудит Contact-фактов выполняется в audit/complete после готового ответа.
Реализация находится в общей невыпущенной области; рабочий Telegram не переключён.
[Карточка](../../docs/components/contacts.md).
