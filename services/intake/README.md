# Приём

Самостоятельный общий вход событий Brai через JetStream. Приём проверяет
доверенный источник и выбирает сквозной сценарий Temporal либо надёжную передачу
через JetStream без Temporal. Сообщение пользователя и каждый ответ Hermes имеют
отдельные процессы, связанные причиной и беседой.

[Контракт](CONTRACT.md), [формат событий и API](schemas/messages.schema.json),
[AsyncAPI](asyncapi.yaml), [поставка и проверка](DEPLOYMENT.md).

## Состав

- main: durable consumer и read-only NATS Services API.
- worker: отдельная task queue Temporal.
- migrate: owner-миграция PostgreSQL, отдельно от runtime.
- deploy/provision: только создание отсутствующих совместимых broker resources.

main и worker читают файл INTAKE_CONFIG. Миграция получает
INTAKE_OWNER_DATABASE_URL и INTAKE_RUNTIME_ROLE отдельным setup-профилем.
[Compose](compose.yml) разделяет runtime, owner SQL и административные NATS inputs.
Файлы секретов находятся вне Git.

## Первый сценарий

Пользовательское сообщение: канал/расположение → контакт → входящие файлы в
Артефактах → Входящие → параллельно Hermes и понимание/память.
Ответ Hermes: готовые ID созданных файлов → Приём → Входящие →
параллельно Telegram-доставка и понимание/память.
Доставка не ждёт независимую память. Ответ не вызывает новый ход Hermes.

Содержимое сохраняется до анализа; снимки и готовый пакет не меняются при
техническом повторе. Состояния передачи брокеру, forwarded и завершения workflow
различаются. Поздний результат сверяется с ожидаемым заданием и исполнителем.

Пример исходного сообщения; source назначается доверенному подключению, внутренние
owner/channel IDs отправитель не задаёт:

~~~json
{
  "version": 1,
  "eventId": "chat-7/message-42",
  "source": "telegram",
  "type": "message.incoming",
  "occurredAt": "2026-10-30T00:00:00Z",
  "correlationId": "conversation-7",
  "causationId": null,
  "data": {
    "materialId": "bot-example/chat-7/message-42",
    "revision": 1,
    "conversationId": "chat-7/topic-1",
    "replyToMessageId": null,
    "author": {"kind": "human", "id": "654321", "name": "Имя"},
    "sourceRef": {"botId": "123456", "chatId": "654321", "threadId": "1"},
    "text": "Сохранить сообщение",
    "attachments": []
  }
}
~~~

## Самостоятельная проверка

Штатные build/check выполняются через component CLI с ID intake. Интеграционный
стенд подключает настоящие PostgreSQL, JetStream, Temporal, Artifacts и History.
Общая приёмка подключает настоящие Каналы и Контакты. Недостающие
Входящие, понимание, память и протокол работы Hermes
предоставляет только тестовый стенд. Его исходники не входят в runtime payload.

Реальный Telegram и работающий Hermes автоматически не переключаются.
Подключение бота/топика и существующего сборщика альбомов — последующая интеграция,
с сохранением авторизации, состава, подписей, восстановления и служебных отправок.
Новый сервис не запускает вторую Telegram-подписку.

Управляющие результаты и resume имеют атомарную защиту source/eventId/hash.
Успешные понимание/память проверяются по MaterialResult/MemoryResult из owner-схемы;
пустой result не завершает обработку. Миграция 002 добавляет их реестр ключей.

Контакты подключены узким owner DTO: запрос и снимок сохраняются неизменяемо.
Пустые имя/username и недоступная фотография не очищают актуальный профиль.
Contact-аудит выполняется в существующем завершающем шаге, не задерживая ответ.

## Целевое теневое подключение

[Контракт наблюдения](SHADOW_CONTRACT.md) закрепляет отдельный message.observed
и workflow без вызова агента или доставки. Hermes сохраняет прежний маршрут
и потоковые ответы. Это документационный проект: код, схемы и запуск ещё
не реализованы; наличие контракта не включает режим.
