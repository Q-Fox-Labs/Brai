# Известные проблемы local-ai

Обновлено 2026-10-07. Production ниже относится к первоначальному выпуску с известными неисправностями. Изолированная приёмка исправленного кандидата завершена; его выпуск и проверка production ещё не завершены.

## Выпущенная версия

Production unit: `brai-local-ai-operation3-production.service`. Контейнер: `brai-local-ai-op3-main-8683b1d1`. Образ: `sha256:8b8e194120f3344a379fcf834618b497761258f2d1827e0e39d5343373162d4e`.

Созданы собственные БД/роли `local_ai`, перенесены проверенные веса обеих моделей, установлен постоянный запуск. Пользователь `local_ai` и его ACL добавлены в существующий NATS; отдельная сверка прошла. Контейнер работает с лимитами 4 CPU и 6 GiB. Доступ к API — через NATS, включая `brai.local_ai.v1.invoke.embed` и `brai.local_ai.v1.invoke.transcribe`.

## Сбои и незавершённые проверки

1. **Полный production API не подтверждён.** Первый проверочный запуск остановился при декодировании отчёта в Ansible. Перед второй попыткой отдельное чтение подтвердило отсутствие фактов всех трёх тестовых вызовов в истории и собственной outbox. После изменения декодера вторая попытка остановилась на проверке типа stdout и в обработчике ошибки. Причина этого сбоя не установлена. Успех production embeddings и распознавания не заявляется.
2. **Отмена исправлена и принята на кандидате.** Прежние failed evidence сохраняют первоначальный отказ. Новая изолированная проверка подтвердила отмену shared load, очереди, подготовки аудио и активного GigaAM, физический выход групп процессов, освобождение аудио и последующий успешный вызов. Production проверяется отдельно при выпуске.
3. **Эксплуатационная матрица кандидата принята.** Живые deadline embeddings/ASR, таймеры обеих моделей, `null`, повторная загрузка, ограниченная очередь и доступность status/cancel, отказ исполнителя, разрыв NATS, SIGTERM и принудительный перезапуск прошли на точном candidate image. Это не заменяет проверку рабочего выпуска.
4. **История и приватность кандидата приняты.** Настоящий history сохранил короткий Core NATS факт без reply; отключённый получатель не изменил ответ и не создал накопления. Проверки БД, событий и логов подтвердили отсутствие контрольного содержимого вызовов. Гарантированная доставка outbox отменена согласованной best-effort семантикой.
5. **Восстановление рабочего выпуска проверено частично.** Прежний изолированный стенд с восстановленными БД и весами прошёл embeddings и короткое распознавание. Новый кандидат отдельно прошёл recovery прерванной установки: после SIGKILL downloader сохранённая операция при startup получила `unknown`. Восстановление release БД и полный совместный откат рабочего выпуска ещё не приняты.
6. **Оставлены прежние тестовые артефакты изолированного стенда.** Публичные аудиофикстуры: `c8a5fc9d-3ed9-41ff-b486-b0c7fc4361a4`, `b77d19f4-4be0-47b5-a97b-c3badd32bbb6`, `8c266277-5916-44bc-953d-4e6a4ae01c39`. Их удаление через artifacts ещё не выполнено. Первоначальный exact180 завершился deadline; причина прежнего отказа не установлена. Новый ordinary кандидат успешно распознал исходные ровно 180 секунд без Python diagnostic observer и отклонил превышение на один кадр. Три прежних артефакта относятся к отдельной очистке выпуска.

## Проверенный кандидат

Application source: `57b1b3432f6dc02d5c6852f6fa2139248ed5e80e`. Image: `sha256:0f41020141723ab487b99d6fc354af048316655ac3911ce772774f23b07ff764`. Runtime и pinned модели не заменялись. Настоящие embeddings, short/long ASR, WAV/FLAC/MP3/OGG, тишина, повреждение, exact180 и artifacts → local-ai → transcription приняты в изолированной среде. Установка прошла проверки hash, отмены во время записи HTTP body, ENOSPC и retry; отдельный SIGKILL downloader подтвердил startup recovery в `unknown`. Сетевой обрыв этим не подтверждается.

Единственный итоговый forwarding run содержал по пять коротких embeddings и ASR: p50 / эмпирический p95 (максимум n=5) суммы ingress+egress составили 6.042 / 34.311 мс и 8.053 / 28.514 мс. Принятый предел 50 мс соблюдён без изменения границ. t3 — возврат локального NATS SDK publish, а не получение потребителем; artifacts/history peers этого замера — fixtures. n=5 не даёт гарантии для всех запросов. После проверки собственные контейнеры и сеть удалены, отсутствие и неизменность production подтверждены отдельно.

Кандидат использует прямой cached путь без SQL на прогретом invoke и один best-effort факт без ожидания истории. В отдельном проходе упрощения удалены прежние тестовые названия outbox и одноразовая Python диагностика; accepted implementation и image остаются указанными выше. Production API, полный откат/восстановление и очистка трёх старых артефактов остаются задачами выпуска.
