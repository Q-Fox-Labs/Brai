# Контракт сервиса transcription

Владелец границы — `services/transcription`. Нынешний выпуск использует только local-ai и четыре независимо запускаемые программы. [JSON Schema Draft-07](schemas/messages.schema.json) — единственный источник DTO; [карта методов](contracts/methods.json) связывает метод с парой `[params,result]`. [Registry](contracts/index.mjs) проверяет DTO без преобразования и без выдачи подробностей невалидного payload. Все прикладные объекты закрыты. Проверка схем не подтверждает соответствие работающих программ.

## Программы и путь данных

| Программа | Ответственность и связи |
| --- | --- |
| Coordinator | Проверяет trusted principal и вход; читает каталог/проверяет артефакт через owner API; выбирает модель; вызывает helper и исполнителя; отправляет факты history; держит оперативный результат. Внешние технологии подключаются адаптерами в сборке. |
| Helper | Единственный владелец PostgreSQL метаданных: настройки, запросы, попытки, revision/fence/lease и outbox истории. Не вызывает NATS и не получает текст/сегменты. |
| Local executor | Одна команда `execute` через опубликованный [owner local-ai](../local-ai/CONTRACT.md); не выбирает модель или замену. |
| External executor | Отдельная программа с явным `EXTERNAL_ROUTE_UNAVAILABLE`, пустым внешним каталогом и `available:false`; внешних вызовов нет. |

Клиент → coordinator → helper admission → fenced dispatch intent → local executor → local-ai. Ответ executor содержит текст только в памяти coordinator; helper атомарно получает terminal metadata и состояние буфера. Coordinator доставляет helper outbox через [owner history](../history/CONTRACT.md). Temporal, providers, notifications, cloud fallback и автоматический повтор вычисления в этот выпуск не входят.

Coordinator проверяет владельца и `ready` через [owner artifacts](../artifacts/CONTRACT.md); executor получает ID артефакта, а не URL, путь или байты. Готовность артефакта не гарантирует удержание его байтов до invoke. Собственная БД, outbox, история, логи и долговечные очереди не содержат аудио, текста или сегментов. Public NATS передаёт только небольшие метаданные. Private owner local-ai Core NATS reply может эфемерно вернуть текст/сегменты: executor передаёт их по stdio в volatile-буфер coordinator. Этот reply не помещается в JetStream, долговечную очередь, outbox или историю. Только HTTP/MCP `result.get` выдаёт текст владельцу, пока жив ограниченный оперативный буфер.

## Доступ, настройки и выбор модели

Principal задаёт проверенный транспорт/сессия или доверенное сопоставление caller в конфигурации runtime. Клиент не задаёт owner, scope, permissions, snapshot или selected model. Trusted owner/scope — ограниченные opaque ID; свободный текст запрещён. Helper доступен coordinator через доверенный локальный канал. Обычные операции требуют `transcription:use`; `settings.set` отдельно требует `transcription:settings:write`.

`PublicSubmitParams` требует UUID `clientIdempotencyKey`, UUID `audioArtifactId`, `requestedModel` и `deadlineAt`; два последних поля допускают `null`. Requested model — `{route,selection,modelId?}`: local требует modelId; external допускает отсутствие modelId и возвращает `EXTERNAL_ROUTE_UNAVAILABLE`. `selection:required` требует указанную модель; `preferred` не разрешает скрытую замену. Текущие settings/snapshot закрепляют `allowReplacement:false` и external disabled. Собственного списка fallback нет. Язык, произвольные параметры, bytes, URL и errorMessage не входят в DTO.

Coordinator сверяет modelId с фактическим каталогом и до admission фиксирует полный выбранный `{modelId,revision,profileId}`. Для исполнения selector должен быть поддержан и установлен; `ready:false` не исключает admission, поскольку owner local-ai `invoke.transcribe` через lifecycle при необходимости загружает установленную модель. `models.list` сохраняет фактическое значение `ready`. Для недоступной требуемой/default локальной модели admission допускает selectedModel:null при проверенном артефакте и актуальном frozen snapshot. Это устойчивый отказ с историей: coordinator выполняет fenced start/finish failed с MODEL_UNAVAILABLE без invoke, без отложенного выбора или фиктивного selector. Сам null не означает MODEL_MISMATCH. Selector допускает канонические `/`, `:`, `.`, `_`, `@`, `+`, `-`, но не свободный текст; безопасный синтаксис не заменяет точную проверку каталога. Requested reference, selected selector и actual selector сохраняются отдельно. Snapshot неизменяем: полный default selector/null, settings, version и SHA-256. При non-null выбранном selector `actualModel` должен совпадать с ним; иначе `MODEL_MISMATCH`, без принятия текста другой модели.

`models.list` использует опубликованные owner `models.list/get` через явный адаптер coordinator; возвращает только selector и declared `supported/installed/ready`. Наличие ready не доказывает успешный invoke. Неподдержанные owner карточки без полного profile не выдаются как исполняемые selector. Недоступная зависимость даёт typed `MODEL_CATALOG_UNAVAILABLE`/`DEPENDENCY_UNAVAILABLE`, не фиктивный успешный пустой каталог. `externalItems:[]`, `externalAvailable:false`. Состояние `unverified` честно обозначает отсутствие проверки runtime.

Helper связывает `clientIdempotencyKey` с trusted owner/scope и SHA-256 нормализованного клиентского input. Canonical input — объект `{audioArtifactId,requestedModel,deadlineAt}`: UUID артефакта переводится в lowercase; requestedModel сохраняется как закрытое значение без смены регистра modelId; deadlineAt сохраняется точной валидной строкой или null без разбора через Date, округления и усечения. Ключ и principal в хеш не входят; verified artifact facts, selected model и policy также исключены. Канонизация рекурсивно сортирует ASCII-ключи объектов лексикографически, сохраняет порядок массивов и сериализует компактным `JSON.stringify`; SHA-256 считается по UTF-8 байтам, результат — lowercase hex. `clientIdempotencyKey` отдельно нормализуется как lowercase UUID. Snapshot hash отдельно вычисляется от `{version:settings.policyVersion,defaultLocalModel,externalEnabled:false,allowReplacement:false}` тем же алгоритмом, без поля `sha256` внутри входа.

`request.lookup` — read-only операция по trusted owner/scope, ключу и ожидаемому нормализованному hash. Она вызывается до чтения artifacts, каталога и текущих settings: при совпадении возвращает прежний RequestRecord, при отсутствии — `{request:null}`, при том же ключе и другом hash — `IDEMPOTENCY_CONFLICT`. Helper повторяет ту же проверку атомарно внутри `request.accept` до проверки новых artifact/model/policy facts, поэтому параллельные lookup/admission не допускают регистрации изменившегося запроса. Повтор с тем же input возвращает сохранённые факты и snapshot, даже если внешние зависимости или policy изменились. Fake artifact, selected model или policy запрещено использовать для решения о повторе. Новая вычислительная попытка после потери требует нового явного запроса и ключа.

## Выполнение, lease и восстановление

Вычисление: `accepted → dispatching → running → succeeded | failed | outcome_unknown | cancelled`. Наличие/выдача текста независимо: `not_ready | available | delivery_unknown | lost | expired`. Helper использует revision CAS и проверяет requestId/attemptId/claimToken/fenceGeneration; поздний или устаревший ответ не меняет активную попытку.

`request.claim` возвращает весь RequestRecord с owner, артефактом, deadline, выбранной моделью и полным snapshot, а также token, fence, revision и expiry. `request.renew` обязателен для законного долгого execute; долгий invoke не блокирует renew/cancel/control RPC. Время и lease определяет БД helper, caller не присылает arbitrary now. Renew использует текущую revision, новую revision передают последующим CAS.

Перед фактическим invoke `attempt.start` устойчиво фиксирует dispatch intent. Только свежий успешный ответ `created:true` разрешает отправить **одну** команду. Повтор start, stale CAS, прочитанная запись intent или повторный receipt не разрешают отправку. Потерянный ответ start оставляет dispatch неоднозначным: coordinator не повторяет compute. attempt.start может зафиксировать fresh intent при уже истёкшем deadline. Если deadline истёк до invoke после зафиксированного dispatch intent, coordinator не вызывает модель, а завершает attempt как failed с `DEADLINE_EXCEEDED`; он не оставляет accepted request и резерв навсегда и не выдаёт deadline за отмену. Разрыв/timeout после возможной отправки и просроченный lease dispatching/running дают `outcome_unknown`. Автоматический invoke, новая попытка и замена запрещены. До dispatch допускается повторное получение accepted работы только при доказанном отсутствии intent.

`attempt.finish` одной транзакцией фиксирует terminal request/attempt metadata, resultState/resultExpiresAt/bufferOwnerInstanceId и заполняет зарезервированный terminal history slot. Outcome `succeeded` допустим только когда coordinator уже удерживает конечный TTL буфер; исходная выдача ставит `available` или `delivery_unknown`. Потеря/истечение буфера после этого переводит resultState в `lost`/`expired`; `result.setState` не воскрешает эти состояния и отклоняет `delivery_unknown` с `STATE_CONFLICT`, если DB TTL уже истёк. При потерянном ответе finish coordinator читает metadata и не повторяет invoke. `recovery.run` получает coordinatorInstanceId; startup единственного coordinator помечает результат другого экземпляра `lost`, сохраняя computed metadata. Recovery по времени БД переводит expired leases в unknown, результаты по TTL — в expired; прежние metadata не запускают модель заново.

До dispatch cancel отзывает claim, атомарно завершает request/history и возвращает `accepted:true,stopConfirmed:true`. In-flight cancel нынешнего выпуска отвечает `false/false`: не переводит running/dispatching в cancelled, не отбрасывает корректный активный ответ и не обещает остановку local-ai. Timeout сам по себе не является подтверждённой отменой.

HTTP завершение и RPC response не доказывают получения текста клиентом. Пока буфер жив, повторное чтение разрешено без compute, в том числе после неизвестной доставки. После потери/TTL возвращается typed result state. Неизвестная доставка не означает неизвестный исход вычисления. Текст не усекается для соблюдения лимита.

## Метаданные, ресурсы и история

RequestRecord сохраняет проверенные mimeType/sizeBytes и `audioDurationSeconds:null`, пока source duration неизвестна. `durationMs` — время обработки, не длина исходного аудио; его нельзя выводить из segments. Неизвестные usage/cost/duration равны `null`, а не нулю. Известная стоимость — точная неотрицательная decimal string с валютой. Local-ai не выдаёт usage/cost: local executor возвращает оба `null`. Helper сохраняет известные usage/cost в DTO и метаданных независимо от route; неизвестное остаётся null.

Конфигурация выпуска обязательно задаёт конечные execute concurrency, число ожидающих результатов, совокупные bytes буфера, bytes одного ответа, TTL, capacity pending history + reserves, claim lease/control timeout и bytes строки RPC/HTTP/NATS. Лимит строки проверяется до newline/JSON parse. Oversized batch не запускает handlers; корректные non-notification вызовы получают OVERLOADED с прежним id, невалидные — стандартную ошибку, notifications остаются без ответа. Если ограниченный response не помещается, канал закрывается без усечения; caller сохраняет неизвестный исход. Control RPC имеют отдельный резерв, поэтому долгий execute не блокирует renew/cancel. Переполнение возвращает typed `INPUT_TOO_LARGE`, `RESULT_TOO_LARGE` или `OVERLOADED`; текст не усекается и новый invoke не начинается. Сервис не вводит собственного ограничения длительности аудио; реальные ограничения выбранного owner runtime возвращаются как явная ошибка.

Admission атомарно записывает accepted event и резерв terminal slot с заранее назначенным ID; оба учитываются в capacity. Заполненный outbox отклоняет admission до регистрации/вычисления. `settings.set` также атомарно меняет настройки и резервирует событие; нехватка места не допускает частичной записи. Terminal slot заполняется успехом, отказом, unknown или отменой, не вытесняется accepted событием.

History envelope ссылается `allOf` на канонический owner `appendRequest`; локальный закрытый `HistoryFact` сужает data и исключает текст/произвольное сообщение. Accepted/dispatching/running имеют `outcome:null`; terminal/cancel — фактический enum outcome. Settings fact содержит phase/version/hash и допускает requestId:null без фиктивного UUID. Актуальные типы history: execute `1201`, cancel `1202`, configure `1301`. Source задаёт доверенный subject `brai.history.v1.append.transcription`; scope/request owner и actor проходят trusted mapping.

`history.claim` возвращает стабильный delivery ID и lease token. Ack/fail требуют актуальный token; stale подтверждение отклоняется. Coordinator повторяет delivery с прежними source/id/DTO; постоянный отказ остаётся учтённым и влияет на backlog/readiness. `HISTORY_DELIVERY_FAILED` означает временный отказ или неизвестный исход append истории: событие остаётся pending и повторяется с прежними source/id/DTO. `HISTORY_REJECTED` означает постоянный owner-отказ; событие остаётся failed, учтено в backlog и ухудшает готовность. Эти коды описывают доставку метаданных, не исход вычисления. Ошибка истории не запускает compute. History append/commit подтверждает сохранение факта владельцем, не доставку текста пользователю.

## Машинные интерфейсы и ошибки

| Граница | Описание |
| --- | --- |
| Helper RPC | [helper.openrpc.json](contracts/helper.openrpc.json): health, settings.get/set, request.accept/lookup/get/cancel/claim/renew, attempt.start/markRunning/finish, result.setState, recovery.run, history.claim/ack/fail. |
| Local/external RPC | [local.openrpc.json](contracts/local.openrpc.json), [external.openrpc.json](contracts/external.openrpc.json): execute, health, cancel. |
| Public NATS | [asyncapi.json](contracts/asyncapi.json): шесть `brai.transcription.v1.*` subjects request.submit/get/cancel, models.list, settings.get/set; result/text subject отсутствует. |
| HTTP | [http.openapi.json](contracts/http.openapi.json): семь POST `/v1/transcription/{method}`, включая dotted `/v1/transcription/result.get`. |
| MCP | [mcp.json](contracts/mcp.json): семь `transcription_request_submit/get/cancel`, `transcription_models_list`, `transcription_settings_get/set`, `transcription_result_get`. |

RPC — JSON-RPC 2.0, UTF-8 stdio NDJSON; только RPC в stdout, безопасная диагностика в stderr. Именованные закрытые params, batch, notifications без ответов, совпадающий id, result/error взаимоисключаются. Parse error `-32700`, Invalid Request `-32600`, Method not found `-32601`, Invalid params `-32602`, Internal error `-32603`; неопределимый id равен null. Прикладная ошибка `-32000` с generic message и закрытым `ErrorResponse` в data. Raw handler exception нормализуется в фиксированную `-32603` без деталей. Транспорт не выводит payload, AJV errors или соседние exception messages. Удалённые `-32603` и `-32000` для операции с побочным эффектом консервативно оставляют исход неизвестным: handler мог уже изменить состояние. Доказанный pre-handler отказ стандартной проверки или гарантированный capacity rejection означает known rejected. Прикладная ошибка никогда не разрешает повтор вычисления. JSON-RPC id сопоставляет ответ и не обеспечивает идемпотентность compute.

NATS Services имеет имя/queue group `brai_transcription`, версию и instance ID, PING/INFO/STATS. Успех — прямой DTO. Ошибка — закрытый `{errorCode}` и оба заголовка `Nats-Service-Error` (safe code), `Nats-Service-Error-Code` (числовой статус). PING не означает готовность всех зависимостей. Ни один adapter не логирует request/result payload. HTTP выдача текста содержит `Cache-Control: no-store`. HTTP/MCP используют те же public DTO; HTTP ошибка содержит ErrorResponse, статус 400/401/403/404/409/413/429/503/504/500 по причине. `DEADLINE_EXCEEDED` возвращается как 504; `HISTORY_DELIVERY_FAILED`, если выходит на публичную границу, — как 503. HTTP deadline не доказывает отмену или отсутствие побочного эффекта. MCP tools/list получает разрешённые owner schema refs, tools/call возвращает structured DTO; tool error не раскрывает сырой exception. Обычный transcript текст не помещается в NATS ошибку или history.

## Local-ai mapping и ограничения проверки

Local executor получает service requestId и уникальный operationId = attemptId. На owner `invoke.transcribe` requestId сохраняет service requestId, а operationId равен attemptId; эти идентификаторы обязаны различаться. Adapter отклоняет совпадающие ID до вызова owner, проверяет оба owner response ID и selector, затем возвращает прежние service requestId и attempt operationId. Один operationId обозначает одну попытку без повторного вычисления. Переданный deadlineAt не переписывается и должен укладываться в явно настроенный предел owner; hop timeout отдельно ограничивает ожидание транспорта. Owner transcribe response `model` становится actualModel, segments и processing durationMs передаются как есть; usage/cost остаются null. Cancel нынешнего выпуска не вызывает owner cancel, всегда false/false; owner `cancellation_requested` не доказывает остановку. Исполнитель не читает/меняет settings, БД, каталог или историю.

Owner local-ai CONTRACT и схемы опубликованы, но реальный invoke/runtime и остановка обработки здесь не проверены. Наличие descriptors/runner adapters не подтверждает работающий local-ai. Принятие внутренних портов возможно отдельно от реальной интеграционной проверки test runtime; форматы, сопоставление IDs, model readiness и byte/resource limits требуют проверки actual сборки. Artifacts может удалить байты до чтения; ошибка нормализуется без повторного invoke. Raw owner history schemas поставляются source side assets рядом с registry; отдельная копия wire DTO в dist не создаётся.
