# Codeworks: техническое устройство

Codeworks хранит рабочие области и координирует операции с Git, GitHub, CI и выпусками. Он не запускает агента и не меняет его разрешения.

[Контракт](CONTRACT.md) описывает lifecycle и API; [дескрипторы компонентов](components/README.md) — discovery, проверки, сборку и поставки; [CI](ci/README.md) — доказательства происхождения артефактов; [Temporal](TEMPORAL.md) — исполнение, восстановление и обновление.

## Клиент и конфигурация

CLI предоставляет prepare, status, sync, release, cleanup, lifecycle.status, release.close, workspace.cancel и workspace.transfer. Публичный prepare продолжает существующую область; новая появляется при первой поддерживаемой файловой записи через hook. Схемы доступны через --schema, справка — через --help. После изменяющего запроса клиент сохраняет ID операции и читает status; неизвестный исход не разрешает повтор с новым ключом.

CODEWORKS_CLIENT_CONFIG указывает JSON с server, credsFile и executorId. credsFile ссылается на защищённый NATS options JSON либо .creds. Переменные CODEWORKS_NATS_URL, CODEWORKS_NATS_CONFIG / CODEWORKS_NATS_CREDS_FILE и CODEWORKS_EXECUTOR_ID переопределяют соответствующие значения.

## Политика проекта

Регистрация проекта задаёт допустимые пути, Git flow и исключения documentation_paths. Каталог в исключениях охватывает вложенные файлы; обычный файл — только его путь. Hook использует ту же политику для распознанных правок. Поддерживаемые native файловые вызовы он перенаправляет в подготовленное дерево; shell в основной копии не переписывается. В готовом дереве до допуска shell-записи проверяется возможность подтвердить её завершение. Поддерживается ограниченный набор foreground команд, включая литеральные перенаправления, cp и rm с допустимыми фиксированными флагами и литеральными целями; неподдерживаемые формы, динамические аргументы и фоновые вызовы отклоняются с WRITER_COMPLETION_UNSUPPORTED. Для уже существующего неизвестного писателя очистка ждёт подлинной сверки. Подтверждение фактического изменения активирует область и её необязательный индекс. Смешанная правка исключённого документа и защищённого кода требует рабочей области.

Это возможности механизма. Обязанности агента, порядок приёмки и настройки конкретной команды задаются вне продуктового контракта.

В shell-командах hook проверяет явные цели записи в поддержанных командах. Тела here-document передаются программе на stdin и не разбираются как команды; записи в заголовке и после тела проверяются. Проект определяется путём файла. Правка соседнего незарегистрированного репозитория из чата защищённого проекта не требует рабочей области. При запрете hook указывает ID и корневой путь проекта.

Историческую очистку оператор может подтвердить защищённым проверенным Git bundle. Архив сохраняет историю, но не заменяет активную ветку и не разрешает очистку активной задачи. Технические сбои после ограниченных попыток SDK повторяются сохранёнными раундами без новой операции; миграция 011 хранит время следующего повтора.

release.close закрывает только попытку выпуска. После поздней подтверждённой доставки feature в DEV явный cleanup может завершить задачу, если дерево и Git refs соответствуют проверенному результату и нет незавершённой работы.
