# Веб-превью рабочих веток

Codeworks публикует веб точного проверенного коммита рабочей ветки до её принятия в DEV. Сервисы и данные остаются общими с DEV; серверные изменения рабочей ветки в превью не устанавливаются.

Оператор включает возможность через `project.web_preview`: `enabled`, ровно два `slots` с уникальными `id` и HTTPS `url`, необязательный `ttl_seconds` (по умолчанию 172800; допустимо от 60 до 604800). Адрес должен быть полным origin без пути, credentials и wildcard. Нужна доверенная CI policy проекта. Без включённой настройки прежний lifecycle работает без изменений.

Новый отправленный коммит активной рабочей области проходит существующий CI verifier. Влияние на веб определяется входами компонента и его зависимостями. Очередь и сведения о запрошенном и опубликованном коммитах сохраняются в PostgreSQL. Устаревшая операция не может заменить более новый запрос.

Проектный Temporal workflow раз в минуту выполняет отдельный ограниченный проход, не задерживая очистку задач. Обрабатываются зарегистрированные активные рабочие области: обычный Git push и `sync` используют один путь. Проверка входов читает точные Git objects, не запускает код ветки и не собирает приложение на сервере. Изменения только тестов или чужих зависимостей lockfile не требуют превью. Смешанная ветка получает отметку `backend_changed`; её серверные компоненты не устанавливаются.

Готовые после CI ветки получают слот по FIFO. Обновление занятого слота возможно и при полной очереди. Ожидающая ветка сохраняет последний HEAD. До первого внешнего действия повторно проверяются lifecycle, удалённый HEAD и PR. При изменении или закрытии ветки уже начатое действие сохраняет неизменную идентичность до сверки и выполняет только необходимый откат, после чего обрабатывается новый HEAD либо освобождение.

Превью использует готовый immutable веб-образ. Обновление может кратко прервать доступ; при неудаче адаптер восстанавливает предыдущую рабочую версию. Публичный статус различает успешную синхронизацию ветки и готовность сайта.

## Статус

`status` выбранной области включённого проекта содержит `preview` (null до первого наблюдения). Состояния: `waiting_ci`, `queued`, `publishing`, `ready`, `failed`, `expired`, `unsupported`, `removing`. `desired_sha` обозначает последний известный запрос, `deployed_sha` — отдельно подтверждённую рабочую версию. Поэтому после ошибки они могут отличаться. `queue_position` задаётся только для очереди; `url`, `published_at`, `expires_at`, `backend_changed`, `shared_backend` и безопасный код `error` дополняют состояние. Proof, секреты и исполняемое намерение не выдаются клиенту.

Публикация или новый явный sync продлевают аренду. Чтение статуса и просмотр сайта её не продлевают. Истечение срока освобождает только ресурсы превью; ветка, рабочее дерево и данные DEV сохраняются.

Истёкший коммит не публикуется заново при фоновом опросе: нужен новый HEAD либо новый успешный `sync` с новым ключом запроса. Продление того же SHA обновляет срок один раз на операцию, без пересборки и перезапуска веба. Принятие задачи, отмена, удаление ветки и закрытие PR освобождают слот только после подтверждённого удаления ресурсов.

## Операторский адаптер

`CODEWORKS_PREVIEW_ADAPTER` указывает установленный оператором executable. Он принимает JSON-RPC 2.0 через stdin/stdout: `publish`, `inspect`, `remove` с `preview_id` и `generation`; [OpenRPC](preview.openrpc.json) определяет схемы. Proof или произвольные пути, образы и переменные через этот интерфейс не передаются. Адаптер сам читает сохранённое намерение и доверенное owner CI evidence.

Все записи координатора и действия адаптера используют один ключ PostgreSQL `codeworks:web-preview:<project_id>`. Координатор держит его только в короткой транзакции и освобождает до вызова адаптера; адаптер удерживает session lock при внешнем действии и прекращает команды при потере соединения. Удаление подтверждается полным наблюдением принадлежащих слоту ресурсов. Неизвестный исход удерживает слот; повтор начинается с `inspect`. `publish` и `remove` — идемпотентная сверка фиксированных ресурсов той же идентичности, а не повтор бизнес-операций. Подтверждение ответа не считается гарантией exactly-once Docker.

Несовместимый protocol marker образа даёт `unsupported`. Предыдущая подтверждённая рабочая версия при этом сохраняется. Публичное `release` не вызывается автоматически: превью не является приёмкой, слиянием или установкой DEV.
