# Сервис целей

Сервис владеет целями, фокусом, записями, ресурсами, потребностями и резервами. Данные других компонентов не копируются. Внешние операции и гарантии описаны в [контракте](CONTRACT.md).

## Устройство

`src/domain.ts` выполняет операции и проверяет резервы в транзакции владельца. `src/api.ts` принимает только известные операции. Web и MCP подключаются к одному ядру; миграция запускается отдельно. `src/rates.ts` обновляет публичные курсы без данных пользователя. `src/stdio-proxy.ts` передаёт локальные вызовы Codex защищённому MCP.

## Конфигурация

Оператор готовит собственную базу и отдельные роли владельца и runtime. Для миграции нужны `GOALS_OWNER_DATABASE_URL`, `GOALS_OWNER_ROLE`, `GOALS_APP_ROLE`. Runtime получает `GOALS_DATABASE_URL`, `NATS_URL`, `NATS_USER`, `NATS_PASSWORD`, `NATS_INBOX_PREFIX`, `GOALS_MCP_HOST`, `GOALS_MCP_PORT`, `GOALS_MCP_OWNER_ID`, `GOALS_MCP_ALLOWED_HOSTS`, `GOALS_MCP_ALLOWED_ORIGINS` и `GOALS_MCP_TOKEN_FILE`. Необязательная `GOALS_BASE_CURRENCY` по умолчанию равна RUB.

Локальный мост получает `GOALS_MCP_URL` и путь `GOALS_MCP_TOKEN_FILE`; значение токена не помещается в конфигурацию и журналы. Сеть и ACL экземпляра должны допускать NATS-команды только от доверенного Web. MCP требует bearer token и привязывает владельца к настройке экземпляра.

## Проверки

`npm test --workspace=@brai/goals` собирает пакет и запускает синтетические тесты. Проверки PostgreSQL используют отдельную базу через `GOALS_TEST_OWNER_DATABASE_URL` и `GOALS_TEST_DATABASE_URL`; без этих входов они пропускаются. Перезапуск проверяется отдельно с `GOALS_TEST_RESTART=true`.

Наличие кода не означает, что сервис установлен или принят. Автоматическое исполнение, уведомления и банковские подключения не входят в этот компонент.
