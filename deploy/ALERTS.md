# Запуск Alerts

[Технический README сервиса](../services/alerts/README.md) описывает контракт, конфигурацию и проверки. Этот раздел описывает готовые определения Compose.

## Постоянный runtime

[compose.alerts.yml](compose.alerts.yml) запускает принятый готовый образ. Он не создаёт БД, роли, секреты или JetStream и не выполняет миграцию автоматически. Порт наружу не публикуется: браузер обращается к авторизованным API и SSE Web на /alerts.

Перед запуском подготовьте отдельные входы приложения и мигратора, стабильный ключ курсоров и совместимые PostgreSQL/NATS. Runtime не получает owner URL. Схему подготавливает отдельная миграция владельца, а runtime проверяет готовность stream и consumer.

## Изолированный тестовый стенд

[compose.alerts-test.yml](compose.alerts-test.yml) описывает удаляемый PostgreSQL/NATS стенд с loopback-портами и tmpfs. Образы и тестовые учётные данные закреплены в этом определении; они предназначены только для тестов. Стенд не подтверждает работу настоящего Auth.

[alerts-jetstream.mjs](alerts-jetstream.mjs) предоставляет provision/verify только для этого фиксированного стенда. Параметры stream, consumer и тестового ACL принадлежат этому исходнику. Для проверок сервиса используйте test runner из технического README.

## Данные и диагностика

Runtime подтверждает ingress после commit. Повтор доставки допускается благодаря ключу (service_id,id). Переполненный stream должен отказывать новым публикациям; отправитель сохраняет сообщение до PubAck.

Резервная копия должна согласованно сохранять PostgreSQL, неподтверждённый ingress JetStream, владельцев и права, входы подключения и стабильный ключ курсоров. Откат совместимого образа сохраняет уведомления, отметки прочтения и backlog. Удаление томов допускается только у собственного одноразового тестового стенда. Порядок выпуска, восстановления и управление доступами определяет оператор экземпляра.
