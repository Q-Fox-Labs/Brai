# Duplicati

Клиентская служба резервного копирования. Общая роль устанавливает официальный
CLI-пакет Duplicati 2.4.0.1 с закреплённым SHA-256 и запускает `duplicati.service`.
Admin использует эту же роль; отдельной реализации для DEV нет.

Веб-интерфейс отключён через `--webservice-api-only=true`. API доступен только
на loopback:8200 и требует пароль. Для управления служат `duplicati-cli` и
`duplicati-server-util`. Установка не открывает внешние порты и не меняет прокси.

Полная установка: `deploy/ansible/install.yml`. Только подготовка Duplicati:

```sh
ansible-playbook -i /secure/client-hosts.yml deploy/ansible/install_duplicati.yml
ansible-playbook -i /secure/client-hosts.yml deploy/ansible/verify_duplicati.yml
```

Требования: Ubuntu 24.04 x86_64, Python 3, systemd, apt, `ss` и HTTPS к GitHub.
Полный установщик готовит необходимые средства до включения роли.

`duplicati_initialize_secrets` по умолчанию false: восстановление требует
прежний `/etc/duplicati/server.env`. Чистая клиентская установка и отдельный
подготовительный плейбук явно разрешают однократную генерацию ключа настроек
и пароля локального API. Повтор сохраняет существующий файл; небезопасные
права, симлинк или отсутствие прежних ключей при restore останавливают роль.

`/etc/duplicati/server.env` имеет root:root 0600; каталоги `/etc/duplicati`,
`/var/lib/duplicati`, `/var/backups/brai-duplicati` — root:root 0700.
Последний каталог зарезервирован для дампов, которые роль сама не создаёт.
Служба работает от root для доступа к закрытым источникам.

Google Drive, OAuth, источники, расписание, срок хранения и пароль шифрования
архивов настраиваются отдельно. Ключ `SETTINGS_ENCRYPTION_KEY` защищает настройки
Duplicati и не заменяет пароль архивов. Для восстановления нужны соответствующие
ключи и настройки; не храните их единственную копию на резервируемом сервере.

Проверка `/usr/local/libexec/brai-verify-duplicati` не читает секреты: проверяет
права, версию, точный unit, включение и работу службы, loopback, отсутствие UI
и обязательную аутентификацию API. Полная установка вызывает её сразу и через
ежедневный `brai-install-verify.service`. Отдельная Ansible-проверка сверяет
также саму программу проверки. Удаление прежних публичных маршрутов конкретного
сервера остаётся миграцией Admin.
