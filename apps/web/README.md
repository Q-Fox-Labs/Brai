# Веб-интерфейс таймера

Одна страница Next.js показывает локальный секундомер и подтверждённую общую историю. Шлюз HTTP/SSE находится в том же Node.js процессе. Веб-приложение не читает БД и внутренний код сервиса таймера.

## Запуск

Из корня: `npm ci`, `npm run build:web`, `npm run typecheck:web`, `npm run lint`, `npm run test:web`. Из `apps/web`: `npm start` или `npm run dev`. Версии Node.js/npm закреплены в корневом package.json.

За обратным TLS-прокси явно задать `WEB_ORIGIN` — канонический публичный HTTPS origin без пути. Проверка Origin использует его; для локального запуска без прокси допустим fallback protocol + Host. Forwarded заголовки самостоятельно не считаются доверенными.

Серверные переменные: `NATS_URL`, `NATS_USER`, `NATS_PASSWORD`, `NATS_INBOX_PREFIX` (по умолчанию `_INBOX.brai_web`). Не задавать их через `NEXT_PUBLIC_*`. Приложение не читает файлы `.env` самостоятельно; оператор передаёт окружение. В браузере остаются только относительные HTTP URL. За TLS и доступ к общему таймеру отвечает оператор.

Один процесс Next.js владеет одним pull durable `web_events` потока `BRAI_TIMER_EVENTS`. Горизонтальное масштабирование с общей durable не поддерживается: события распределились бы между процессами. Рестарт процесса и потеря событий за срок хранения восстанавливаются через snapshot и command ledger. Браузер сохраняет ограниченную очередь намерений и локальный отсчёт целиком в sessionStorage.

## Контракт HTTP/SSE

Владелец HTTP/SSE — это приложение. Wire DTO и машинные схемы принадлежат [сервису таймера](../../services/timer/README.md), [commands](../../services/timer/schemas/commands.schema.json) и [messages](../../services/timer/schemas/messages.schema.json); сервер валидирует эти owner schemas напрямую. События не получают дополнительных бизнес-полей.

| Метод | Запрос | Успешный ответ |
| --- | --- | --- |
| POST `/api/timer/start` | StartCommand | 202 `{commandId,status:"queued"}` только после PubAck |
| POST `/api/timer/stop` | StopCommand | такой же 202 |
| GET `/api/timer` | нет | SnapshotResponse |
| GET `/api/timer/history?cursor=…&limit=50` | HistoryRequest; limit 1..100 | HistoryResponse |
| GET `/api/timer/commands/{commandId}` | CommandLookupRequest | CommandLookupResponse |
| GET `/api/timer/events` | нет | SSE `snapshot`/`change` |

POST принимает JSON не более 2048 bytes; неверный вход отклоняется до публикации. Дополнительные поля запрещены owner schema. Чужой Origin получает 403. Курсор передаётся сервису без собственного кодирования. Чтения не кешируются.

Ошибки: `{code,outcome}`. 400/413/415/403 означают отказ до публикации. 503 `PUBLISH_REJECTED` — явный отказ брокера, `outcome:"not-published"`; 502 `PUBLISH_UNKNOWN`, `outcome:"unknown"` — публикация могла сохраниться. Повтор всегда использует исходные body и commandId. `UNAVAILABLE` означает недоступность границы. Чтение результата с 404 `NOT_FOUND` означает только отсутствие завершённого ledger результата; команда может находиться в очереди. Окончательное отклонение команды приходит как RejectedEvent в ledger/SSE, а не как HTTP 202 error.

SSE подключает подписчика до snapshot и буферизует до 64 событий. `snapshot` data — SnapshotResponse, `change` data — StartedEvent, StoppedEvent или RejectedEvent. Повторы ограниченно устраняются по eventId; версия защищает состояние и после вытеснения ID. Любой окончательный результат разрешает запись очереди по commandId независимо от версии. Пропуск версии закрывает поток; новая связь всегда начинает со свежего снимка. Раз в 15 секунд поток передаёт heartbeat без запроса к сервису. Очередь клиента ограничена 64 frames плюс один transport frame, подписчиков не более 128. Переполнение отключает клиента; history/ledger не теряются. ACK брокеру подтверждает bounded разветвление, не просмотр события браузером.

## Локальный отсчёт и сохранение

Кнопка всегда доступна: START начинает новый локальный интервал с новым timerId, STOP сразу показывает `00:00:00`, следующий START начинает с нуля. Состояние связи и ожидающие результаты не блокируют эти действия. История и её активная строка показывают только подтверждённое состояние владельца; она может временно отличаться от локального отсчёта.

Новые тела START — `{commandId,timerId,startedAt}`, STOP — `{commandId,timerId,stoppedAt}`. Они используют owner schemas; время — канонический UTC ISO `YYYY-MM-DDTHH:mm:ss.sssZ`, ровно три цифры миллисекунд и секунды 00–59. Начало фиксируется в момент нажатия по свежему serverTime anchor + performance.now; до первого снимка начальный epoch берётся один раз из часов устройства. STOP фиксирует исходное начало + монотонную длительность. Задержка обработки не увеличивает интервал. Тики вычисляются от anchor, не накапливаются; часы больше суток не обнуляются.

Очередь `brai.timer.outbox.v1` содержит не более 512 неизменных command body/ID, accepted/unknown metadata и локальное состояние. Публикация требует успешного сохранения записи в sessionStorage. При ошибке хранилища действие остаётся локальным и интерфейс сообщает о риске; отправка возобновляется после успешного сохранения. При заполнении очереди новые действия остаются локальными с явным сообщением, что они не появятся в истории. Старые записи не вытесняются. Повреждённое сохранённое содержимое сохраняется без замены, отправка новых действий прекращается; локальная кнопка работает.

Один publisher отправляет команды вкладки FIFO; после PubAck202 сразу отправляет следующую, не ожидая обработки владельцем. Проверка owner ledger работает отдельно и не задерживает новые публикации. После unknown повторяет только исходное body/ID. После PubAck повторной публикации нет, даже при NOT_FOUND. Accepted результаты проверяются раз в две секунды, до восьми последовательных lookup за проход и не более одного одновременно. Только окончательный ledger/SSE результат удаляет запись. Временная недоступность не отменяет принятую команду и не создаёт новый ID.

Reload восстанавливает всю очередь, accepted metadata и локальную длительность. Между документами elapsed дополняется временем часов устройства; внутри документа используется только performance.now. Ранее сохранённая `brai.timer.pending.v1` переносится с исходными legacy body/ID и проверяется через ledger; неизвестный результат допускает повтор того же тела. Повреждённый исходный blob не удаляется. Закрытие клиента отменяет in-flight HTTP и SSE, очередь остаётся для reload.

Несколько окон используют один общий owner: START при активном интервале и STOP чужого timerId получают окончательный отказ. Интерфейс сообщает, что действие не записано; локальный отсчёт остаётся доступным. Пока свои намерения ожидают результата, поздние события и снимки изменяют только историю. Overlay снимается только успехом последнего локального намерения и при подтверждённой версии не ниже его результата. Отказ или действие за пределом очереди сохраняет локальное состояние; поздний успех старой команды его не заменяет. Когда собственные намерения успешно подтверждены, локальный отсчёт следует общему состоянию.

Возврат видимой страницы обновляет снимок и serverTime anchor. Pageshow запускает resync только при возврате из bfcache. История сохраняет ранее загруженные страницы при live updates и resync. Если свежие 50 записей не пересекаются со старой историей, загрузка следующих страниц начинается с нового owner cursor, чтобы заполнить промежуток после долгого отключения.
