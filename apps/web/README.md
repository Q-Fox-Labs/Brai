# Веб-интерфейс Brai

Next.js показывает вход по почте и шестизначному коду, личный таймер и страницу агента `/agent`. Сервер обращается к auth, timer и agent через NATS. Браузер использует HTTP/SSE; веб-приложение не читает БД или внутренний код сервисов. Схемы принадлежат [auth](../../services/auth/README.md), [timer](../../services/timer/README.md) и [agent](../../services/agent/README.md).

## Навигация и тема

Верхняя панель содержит вкладки «Агент», «Таймер» и «Дела». Адреса: `/agent`, `/` и `/do`. Общая тёмная оболочка, включая вход, не перезагружается при переключении. Посещённые экраны остаются в памяти до выхода или смены аккаунта: чат, черновик, настройки, история, очередь таймера и локальное дерево дел сохраняются. Скрытые клиенты агента и таймера продолжают получать обновления; каждый экран создаётся только при первом посещении своей вкладки. Выход прекращает запросы и SSE.

[«Дела»](app/do/README.md) — интерактивный задачник с синтетическими данными: раскрытие дерева, цветные индикаторы, перенос с автопрокруткой, нумерация и панель подробностей. Его изменения живут только в памяти; API и БД задач не подключены.

## Запуск и конфигурация

Из корня: `npm ci`, `npm run build:web`, `npm run typecheck:web`, `npm run test:web`. Из `apps/web`: `npm start` или `npm run dev`. Версии закреплены в package.json и lockfile.

Сервер получает `NATS_URL`, `NATS_USER`, `NATS_PASSWORD`, `NATS_INBOX_PREFIX` (по умолчанию `_INBOX.brai_web`) и `WEB_ORIGIN` — канонический публичный HTTPS origin без пути. Для локального прямого запуска origin берётся из URL запроса. Эти переменные не имеют префикса NEXT_PUBLIC. Приложение не читает секретные .env файлы самостоятельно.

`WEB_TRUST_PROXY` по умолчанию выключен. Включать значением `true` можно только при закрытом ingress за доверенным reverse proxy, который заменяет недоверенный X-Forwarded-For. Тогда сервер передаёт auth только последний адрес XFF, проверенный как IP. Без этого настройки XFF не передаётся; ограничение частоты auth использует общий fallback.

## Вход и выход

POST `/api/auth/send-code` принимает `{email}`. POST `/api/auth/verify-code` принимает `{email,otp}`; otp — строка ровно из шести цифр. JSON ограничен 2048 bytes; дополнительные поля отклоняются схемой владельца. GET `/api/auth/session` возвращает только `{user:{id,email}}`; отсутствие или истечение сессии, а также отказ владельца со статусом 401/403 дают 401. Ответ владельца с временным отказом (429/5xx), неожиданным статусом или некорректной оболочкой ответа по схеме владельца даёт 503 `{code:"AUTH_UNAVAILABLE",outcome:"not-published"}`. POST `/api/auth/sign-out` отзывает текущую сессию и после подтверждения закрывает её SSE. Все мутации требуют совпадающего Origin. Каждый Set-Cookie auth передаётся отдельным заголовком; session token не возвращается в JSON.

Отправка кода и вход выполняют по одному NATS request-reply с timeout 10 секунд без автоматического повтора. Неопределённый исход проверки кода восстанавливается проверкой текущей сессии. Неудачный выход не показывается как успешный. Интерфейс прекращает запросы/SSE перед выходом; при неудаче снова открывает клиент прежнего аккаунта. Проверка текущего аккаунта каждые две секунды обнаруживает выход или вход в другой вкладке.

## Личный HTTP/SSE контракт

Все операции таймера требуют текущей сессии Better Auth. Каждый HTTP запрос клиента передаёт `X-Brai-User` с ID аккаунта документа; SSE использует query `expectedUserId`. Сервер сравнивает это ожидание с проверенной сессией; отсутствие или несовпадение даёт 401 до чтения и публикации. Эти поля не предоставляют полномочий. Сервер добавляет доверенный userId в v2 DTO только после проверки сессии; тело браузерной команды с userId запрещено. Это исключает перенос очереди прежнего аккаунта под cookie другого аккаунта при смене входа в соседней вкладке.

| Метод | Запрос | Успешный ответ |
| --- | --- | --- |
| POST `/api/timer/start` | `{commandId,timerId,startedAt}` | 202 `{commandId,status:"queued"}` после PubAck |
| POST `/api/timer/stop` | `{commandId,timerId,stoppedAt}` | такой же 202 |
| GET `/api/timer` | нет | SnapshotResponse |
| GET `/api/timer/history?cursor=…&limit=50` | limit 1..100, непрозрачный cursor | HistoryResponse |
| GET `/api/timer/commands/{commandId}` | commandId | CommandLookupResponse |
| GET `/api/timer/events?expectedUserId=…` | ID аккаунта документа | SSE snapshot/change/heartbeat |

POST принимает JSON до 2048 bytes. Схемы, временные метки и идемпотентность принадлежат таймеру. Ответы не кешируются. Ошибка `{code,outcome}` различает отказ до публикации (`not-published`), неизвестный исход PubAck (`unknown`) и чтение (`query`). 404 NOT_FOUND результата не доказывает отсутствие команды в очереди. Принятая команда сохраняет userId владельца при выходе, повторе и обработке; новая сессия её не переназначает.

Один процесс владеет pull durable `web_events` в `BRAI_TIMER_EVENTS_V2`. Общая durable между несколькими web процессами не поддерживается. Hub отправляет события только соответствующему userId. Подписка присоединяется до snapshot; bootstrap и transport очереди ограничены 64 событиями, клиентов не более 128. Переполнение или gap версии закрывают поток; свежий snapshot восстанавливает состояние. ACK означает bounded fan-out, а не получение браузером.

Перед каждым frame сервер заново проверяет сессию и совпадение её ID/владельца. Каждые две секунды heartbeat выполняет ту же проверку, даже если таймер не меняется. Потеря сессии или ошибка auth закрывают поток; успешный выход немедленно закрывает все потоки этой сессии в процессе. Уже переданные transport bytes нельзя отозвать. SSE не воспроизводит события v1.

## Агент: HTTP/SSE

Защищённая `/agent` использует существующий Account. Web проверяет текущую сессию, Origin для мутаций и ожидаемый user id. Доступ к Codex socket/profile у web отсутствует.

`BRAI_AGENT_ALLOWED_EMAILS` задаёт разрешённые адреса через запятую, например `owner@example.test,operator@example.test`. Задавайте адреса в нижнем регистре; сервер удаляет пробелы по краям элементов и сравнивает адрес с подтверждённой почтой текущей сессии без учёта регистра. Пустое значение запрещает все операции agent: HTTP 403 `AGENT_ACCESS_DENIED`. Вход по почте и личный таймер работают независимо от этого списка.

GET `/api/agent/<action>` читает `projects/status/threads/open/turns/items/activities/item`; поля передаются query. POST `/api/agent/<action>` принимает `create/start/steer/interrupt/answer`, с JSON body без action. Единственный закрытый контракт принадлежит [agent](../../services/agent/README.md). Мутации автоматически не повторяются; unknown сохраняет черновик и требует проверки чата.

GET `/api/agent/events?expectedUserId=…` открывает один SSE на аккаунт. Подписка подключается до GET `projects`; событие `ready {generation}` подтверждает поколение и доступные configured проекты. `agent` передаёт оболочку `{projectId,threadId,generation,epoch,seq,event}`: первый кадр чата и новый epoch содержат AG-UI `STATE_SNAPSHOT`, следующие — стандартный `STATE_DELTA` (RFC6902) с дополнительным `baseSeq`. Diff строится от последнего переданного снимка. Кадр до1MiB, снимок до512KiB; сервер хранит до16 последних ожидающих и16 отправленных снимков, по одному на чат. Старые pending снимки заменяются новыми. GET с явными projectId/threadId сохраняет прежний wire с полными снимками.

Клиент восстанавливает snapshot библиотекой `fast-json-patch`, проверяет исходную native оболочку и применяет состояние через официальный `@ag-ui/client defaultApplyEvents` и upstream EventSchema. Несовпадение baseSeq требует нового GETopen, старые seq игнорируются. Одновременно применяются один снимок и последний ожидающий; очереди посимвольного воспроизведения нет. До16 баз SSE сохраняются и до первого выбора чата: HTTPopen может опережать последний переданный кадр. До8 последних чатов сохраняют passive SDK состояние и получают фоновые события через общий SSE. Выбор чата меняет только получателя, без нового соединения или open. При первом посещении, настоящем разрыве, смене generation/epoch или вытеснении нужен свежий open. Мутации и старые формы до подтверждения блокируются. Dispose закрывает HTTP/SSE/SDK. История запрашивается отдельно через native cursor.

Каждые пять секунд heartbeat проверяет сессию, разрешённую почту и поколение сервиса. Единичный временный сбой status допускается; три подряд, отзыв сессии, NATS reconnect или смена поколения закрывают поток и требуют свежего состояния. Переполнение очереди, повреждённый кадр и отмена освобождают подписку.
Проекты и их чаты сгруппированы в левой панели. Каждая группа сначала показывает пять названий; «Показать больше» раскрывает загруженный список и затем читает следующую native страницу. Выбранный чат выделен; длинное название сокращено в строке и доступно полностью через подсказку. Справа история прокручивается отдельно от закреплённого поля сообщения. На узком экране панель открывается кнопкой «Чаты».

## Локальный отсчёт и очередь

START/STOP мгновенно меняют локальный отсчёт независимо от доступности timer. Подтверждённые интервалы приходят через snapshot, SSE или ledger. Время фиксируется при нажатии по serverTime + performance.now; задержка обработки не увеличивает интервал. Reload дополняет elapsed разницей wall-clock, внутри документа отсчёт монотонный.

Каждый аккаунт имеет отдельный sessionStorage ключ `brai.timer.outbox.v2:<encoded userId>`. Ключи `brai.timer.pending.v1` и `brai.timer.outbox.v1` не читаются и не импортируются. При смене аккаунта старый клиент размонтируется, отменяет HTTP и SSE; его очередь сохраняется только под исходным аккаунтом.

Общий SSE agent передаёт `limits {generation,limits}` из периодического status. Кадр содержит только закрытую проекцию владельца, проверенную `validateLimits`; отсутствие или некорректная проекция даёт `unavailable`, временный сбой — `stale`. Медленный клиент удерживает не более одного последнего кадра лимита. Клиент хранит отдельную проекцию аккаунта и принимает свежий снимок после переподключения, даже если revision не изменилась. Нижний блок левой панели показывает primary/secondary окна, остаток и сброс в часовом поясе браузера; неизвестный сброс не подменяется датой или восстановленным процентом.

Рядом с названием окна отображается время до сброса: полные дни и оставшиеся часы, при остатке меньше суток — только часы. Под полосой квоты тёмно-зелёная полоса показывает долю оставшегося времени относительно `windowDurationMins` (для недели — семь суток), ограниченную 0–100%. Отсчёт обновляется каждые 30 секунд. При неизвестном времени сброса отсчёт и полоса времени скрыты; при неизвестной длительности скрыта только полоса времени.

При задержке обновления панель сохраняет последние значения без мигающих служебных надписей. Пояснение о задержке доступно при наведении на панель.

FIFO ограничен 512 неизменными намерениями. Публикация требует сохранения в sessionStorage; повреждённое хранилище не перезаписывается. Ошибка или заполнение очереди показываются пользователю. PubAck позволяет отправить следующую команду без ожидания обработки. Unknown повторяет исходный body/ID; accepted не публикуется снова даже после NOT_FOUND. Lookup выполняется раз в две секунды, до восьми последовательных результатов за проход. Только окончательный результат удаляет намерение. Поздний ответ старого действия не заменяет последнее локальное действие.

На `/agent` переподключение сохраняет показанные сообщения и черновик; отправка и формы ждут свежего состояния. SSE передаёт изменения не чаще одного раза за50мс: промежуточные снимки объединяются, полная история на каждый символ не отправляется. Сигнал связи каждые пять секунд поддерживает поток в паузах. Единичный сбой проверки статуса не закрывает соединение; три последовательных сбоя требуют переподключения, проверка сессии остаётся строгой. При открытии чат прокручивается вниз; поступление сообщений следует за нижним краем, пока пользователь не прокрутил вверх. Загрузка прежних сообщений сохраняет позицию чтения.

Следование ленты включается только у самого нижнего края (допуск1пкс для округления браузером). Позиция проверяется до применения snapshot, даже если scroll event ещё не обработан. Последовательные действия между сообщениями объединяются в закрытый блок «Думаю». Закрытая группа не монтирует список: `activities` читает только заголовки партиями до100ID одного хода. Раскрытие действия читает `item`; команда, вывод и diff показываются точным текстом. Ошибка чтения допускает ручной повтор. Кеши разделены по generation/epoch/project/thread/turn/item/revision: до256 заголовков и16 полных действий, максимум4 параллельных чтения и64 ожидающих. Открытая группа обновляет заголовки и раскрытый detail при изменении revision; поздний ответ после смены чата игнорируется.

Сохранённая страница истории и живое окно объединяются по общим ID с сохранением порядка обоих окон; ранние элементы более длинного живого окна не добавляются после итога. Запрос разрешения показывает причину, непосредственные кнопки разового разрешения и отказа, подробности команды по раскрытию. Решения с изменением политики и разрешение на сеанс доступны отдельно с понятным описанием; ответ сохраняет исходное значение Codex без расширения прав.

Повторный выбор одного из8последних открытых чатов сразу показывает его snapshot, до1000 элементов history, draft и выбор модели/рассуждения из памяти текущего аккаунта. Дисковое хранение и отдельные фоновые подключения не используются; controls ждут свежий SSE. History повторно читается при отсутствии страницы, смене generation/epoch или отсутствии пересечения окон после долгого перерыва. Поздние ответы не меняют другую selection. GET `/api/agent/models` читает owner каталог; перед новым заданием selector показывает только его model/effort. Выбор передаётся POST start и сохраняется отдельно по чату; активный steer не меняет настройки.

Третий selector — «Разрешения»: default «Подтверждать за меня», также доступны «Запрашивать разрешение» и «Полный доступ». Выбор сохраняется в том же cache по чату, передаётся create/start и блокируется на время активного хода. Пользовательский config.toml не является доступным preset: интерфейс показывает только реализованные native режимы.

Справа от работающего чата показан индикатор с доступным именем «Агент работает»; reduced motion выключает вращение. Metadata всех чатов обновляется общим SSE без фоновых open. Порядок задаёт `lastMessageAt` (Unix ms) последнего сообщения пользователя или агента; служебный `updatedAt` не влияет, равные метки сохраняют порядок списка.

Ответы агента и сообщения пользователя используют безопасный Markdown: ссылки, code, списки, заголовки, цитаты и таблицы. HTML остаётся текстом; исполняемые URL запрещены. Три селектора имеют доступные имена без видимых подписей. «Отправить» запускает новый ход с текстом или изображениями. Во время хода текст или вложения дают «Скорректировать» (steer), отсутствие обоих — «Стоп» (interrupt). Ctrl/⌘+Enter выполняет ту же команду. Блокировки связи, мутации и неизвестного результата сохраняются.

Кнопка «+» выбирает несколько PNG, JPEG или WebP; Ctrl/⌘+V в поле сообщения добавляет файлы из буфера обмена. Обычная текстовая вставка сохраняется. Предпросмотр показывает имя файла, кнопку удаления и отметку «Уменьшено» для подготовленной копии. Поддержку изображений и допустимое число вложений интерфейс читает из свежего каталога владельца. Во время активного хода используется только фактическая модель чата.

Пределы Brai: до 8 изображений, суммарно 640 КиБ данных до base64. Исходный файл — до 20 МиБ и 32 миллионов пикселей. Помещающийся оригинал отправляется без изменения; большой файл преобразуется в JPEG/WebP с длинной стороной до 2048 пикселей. Подготовка по одному файлу и ограниченная очередь защищают браузер от параллельного декодирования. Копия не уменьшается ниже 512 пикселей по длинной стороне (либо исходного размера); если места недостаточно, файл отклоняется с причиной, предыдущие вложения сохраняются. SVG, неверный MIME и повреждённые файлы отклоняются.

Вложения входят в черновик каждого из восьми сохранённых чатов и живут только в памяти текущего аккаунта. Смена чата, модели или аккаунта отменяет вставку позднего результата подготовки. После accepted удаляются только отправленные изображения из исходного чата; правки текста во время отправки сохраняются. Отказ и unknown сохраняют черновик. Неизвестный исход блокирует повторную отправку и показывает просьбу проверить чат. История показывает `imageCount` пользователя; binary владелец в историю и SSE не передаёт.

Для нового чата название/preview Codex из списка сохраняется, когда более свежие события передают пустую пару title/preview. Свежие статус, активность и время сообщения остаются актуальными. Непустое новое имя или preview заменяет прежнюю пару; metadata разных ID не смешивается.

Служебное сообщение `send_user_message_question_reply` показывает вопрос и выбранный ответ без JSON, тегов и протокольного ID. Распознаётся только полная корректная запись; обычный JSON и повреждённые сообщения сохраняют исходное отображение. История Codex не меняется.
