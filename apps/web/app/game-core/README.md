# Карта Элементов

`/game-core` получает личную карту через `GET /api/game-core` и серверную проверку сессии. Game-core остаётся владельцем Элементов, Ходов, попыток и ресурсов. UI не создаёт копии записей и не меняет API ресурсов.

У каждого Хода один UUID и один владелец. Постановка и приёмка родителя также видны в карточке целевой Задачи. У ребёнка один список: общая постановка, вся собственная цепь с доработками, общая приёмка. Из этого списка получаются номера 1…N, счётчик, строки карты и контекст правой панели. Собственная цепь учитывает предшественников через пропущенные записи.

На полотне спокойная линия без наконечника и ресурсной подписи соединяет только две проекции одной общей Операции по её UUID. Оба порта измеряются по боковой границе конкретной DOM-строки. Если строки нет, линия не рисуется; подмены якоря границей карточки нет. Разнесённые по горизонтали строки соединяются обращёнными сторонами; обе контрольные точки лежат в промежутке. При общем диапазоне X используется ближайший наружный коридор. Стороны пересчитываются при переносе через другую карточку. Координаты следуют масштабу, перемещению и росту содержимого. Ресурсные связи остаются в данных и правой панели, но не рисуются глобально. У ребёнка есть именованный переход к родителю, у общей Операции — к Задаче. Наведение и клавиатурный фокус подсвечивают обе проекции.

Карточки различают Операцию и Действие крупным знаком исполнителя и отдельной формой значка. Статус всегда имеет собственные подпись и знак, поэтому не теряется среди цветовых состояний. UUID, системные коды и поля API не показываются.

Начальная раскладка группирует родителя и его детей. Сохранённые вручную координаты и масштаб продолжают храниться в `localStorage` отдельно для аккаунта. Все Ходы остаются раскрытыми без внутренней прокрутки. Полотно занимает рабочую область; постоянные кнопки — «Новая Задача» и «Вся карта». Фон можно перетаскивать, колесо и клавиши `+` / `−` меняют масштаб, а верхняя строка карточки перемещает её.

Подробности открываются в боковой панели. Ресурсы показывают содержимое и происхождение; их API и ссылки остаются прежними. Для DEV сохранены четыре ручных статуса Элемента (`draft`, `active`, `completed`, `cancelled`) и четыре статуса Хода (`planned`, `claimed`, `succeeded`, `cancelled`). Ручной статус меняет только статус выбранной записи и не создаёт попыток, результатов или ресурсов.

Проверка модели: `node --test apps/web/tests/game-core-board.test.ts`. Полную визуальную приёмку выполняют в настоящем браузере.

Значки ролей используют одну ячейку 36×36 и SVG 24×24 на карте и в панели. Человек показан в красном круге, робот без подложки; статус не меняет оформление роли. Подстрочных дублей «Запуск для» и «Приёмка для» нет.

Карта дополнительно показывает передачу только подтверждённого ресурса между соседними дочерними элементами: общий accept производителя → общий start получателя в детских карточках. Основание — resource.attemptId → attempt.moveId производителя, выход родительской Операции, вход целевого элемента и фактически переданные target_input_resource_ids постановки. Если план задаёт required_outputs, стрелка появляется только при совпадении UUID producer Хода, output_key и plan_revision_id. Прочие потребления не рисуются. Направленная тёплая стрелка отличается от нейтральной identity линии; название ресурса доступно при наведении. Геометрия использует те же измеренные строки и обращённые стороны. Видимые подписи типа/роли удалены; значки сохраняют доступное название.

«Новое поручение» сохраняет исходный запрос и существующую Операцию постановки. Напарник определяет начальный вид Элемента; до первой принятой постановки его можно уточнить без смены ID. «Начать постановку» открывает попытку; её продолжает напарник через агентный канал и owner API packet/bind/build/apply. Принятый план появляется как реальный ресурс. Перед Действием доступны минимальные реальные входы из query.moves: план для подтверждения, полученный результат для рассмотрения. Операции расширения и уточнения плана используют тот же сценарий запуска; служебный маркер сбора не запускается как самостоятельный Ход. Human решения сохраняются через сессию браузера и точную ревизию. Замечание к итогу добавляет доработку и повторное рассмотрение; техническая ошибка оставляет прежний Ход для новой попытки. Ручные DEV статусы в этом цикле не участвуют.
