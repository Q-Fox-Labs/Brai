# Карта Элементов

`/elements` читает личную карту из game-core через `GET /api/elements` и серверную проверку сессии. Владелец задаётся только сервером. API использует no-store. Ресурсы, попытки и правые карточки приходят из БД; обновление страницы не меняет историю. `demo.json` остаётся только fixture для проверки геометрии и статусов. Он не загружается runtime.

Ход показывается в карточке владельца. Рабочие записи имеют UUID. Короткие G1/T1 и A/R остаются только метками тестового fixture. Номер Хода вычисляется по цепочке предшественников отдельно внутри каждого владельца и не хранится в наборе. Межэлементные предшественники сохраняются; при подсчёте номера чужие Ходы пропускаются. В карточке и подробностях используется один локальный номер. Независимые ветви могут иметь одинаковый номер. Целевой Элемент и предшественник указаны отдельно в подробностях. Входы попытки содержат все накопленные ссылки; ресурсы раскрывают содержание и создавшую попытку. Приёмка остаётся у Цели. Её выход одновременно является результатом дочерней Задачи.

Пунктирные стрелки показывают родителя и детей. Сплошные стрелки показывают передачу результата следующей Задаче и возврат родителю при приёмке. Накопленные транзитивные входы не дублируют линию следующей Задачи. Полный набор доступен в подробностях Хода.

Полотно занимает всю рабочую область оболочки. Единственный постоянный контрол — иконка «Вся карта» поверх полотна. Фон можно тянуть, колесо и клавиши + / − меняют масштаб, верхняя строка перемещает карточку. Двойное нажатие верхней строки приближает карточку. Стрелки клавиатуры перемещают сфокусированное полотно или верхнюю строку карточки. Раскладка, масштаб и положение просмотра сохраняются в localStorage отдельно по аккаунтам. Сохранённые данные не меняют зависимости. Блокировка localStorage оставляет карту работоспособной в памяти.

Проверки геометрии и целостности примера: `npm run test:web`. Проверка взаимодействий требует настоящего браузера.

Карточки растут по содержимому: все Ходы открыты, внутренней прокрутки нет. ResizeObserver измеряет высоту после готовности шрифта и при изменении текста. Реальные границы используются в первоначальном расположении, точках линий, приближении карточки и общем обзоре. Раскладка версии 1 мигрирует в версию 2: только пересекающиеся выросшие карточки сдвигаются вниз; остальные координаты сохраняются. В версии 2 ручное размещение сохраняется точно.

Статусы следуют контракту Elements: Элементы draft/active/completed; Ходы planned/claimed/succeeded. Исторический completed у Хода отображается как succeeded. Черновик/план имеет серый пунктир и значок окружности, работа — янтарную рамку и значок запуска, завершение — зелёную рамку и галочку. Подпись дублирует цвет. В demo G1 и T2 — active, T1 — completed, T3 — draft. У G1 пять succeeded, затем один claimed и четыре planned; у T1 три succeeded; у T2 три succeeded, затем один claimed и один planned; у T3 пять planned. Это иллюстрация состояний, а не изменение исторического исполнения. ID, предшественники и происхождение ресурсов сохранены.


Клик по заголовку или свободной области карточки открывает Элемент в существующей правой панели. Кнопка с захватом по-прежнему перемещает карточку; двойное нажатие приближает её. Клик по строке открывает только Ход. Движение с захватом от пяти экранных пикселей подавляет последующий клик, поэтому drag карты или карточки не открывает подробности. Заголовок доступен с клавиатуры.

Панель Элемента отличается заголовком «Элемент · Цель/Задача», значком слоёв и цветным блоком; она показывает описание, уровень из kind, статус, родителя, версию, собственные Ходы с локальными номерами и ресурсы. Панель Хода отмечена «Ход · Операция/Экшен · №…» и значком списка; прежние сведения о владельце, цели, предшественнике и попытке сохранены. Рамка, фон и значок обеих панелей следуют общему status mapping. Список Ходов, родитель и происхождение ресурсов ведут к соответствующей записи в этой же панели. Закрытие и Escape не меняют раскладку.
