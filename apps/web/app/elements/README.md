# Карта Элементов

`/elements` — карта в общей оболочке Brai. `screen.tsx` принимает `BoardData` и строит карточки по ID. В `demo.json` находится обезличенная симуляция конечного снимка: G1, три Задачи, 23 выполненных Хода и 26 ресурсов. Это исторический пример, а не данные текущего аккаунта. Реальные API, БД, платежи и действия не подключены.

Ход показывается в карточке владельца. Короткие G1/T1 и A/R — метки демонстрации, а не формат будущих реальных ID. Номер Хода вычисляется по цепочке предшественников отдельно внутри каждого владельца и не хранится в наборе. Межэлементные предшественники сохраняются; при подсчёте номера чужие Ходы пропускаются. В карточке и подробностях используется один локальный номер. Независимые ветви могут иметь одинаковый номер. Целевой Элемент и предшественник указаны отдельно в подробностях. Входы попытки содержат все накопленные ссылки; ресурсы раскрывают содержание и создавшую попытку. Приёмка остаётся у Цели. Её выход одновременно является результатом дочерней Задачи.

Пунктирные стрелки показывают родителя и детей. Сплошные стрелки показывают передачу результата следующей Задаче и возврат родителю при приёмке. Накопленные транзитивные входы не дублируют линию следующей Задачи. Полный набор доступен в подробностях Хода.

Полотно занимает всю рабочую область оболочки. Единственный постоянный контрол — иконка «Вся карта» поверх полотна. Фон можно тянуть, колесо и клавиши + / − меняют масштаб, верхняя строка перемещает карточку. Двойное нажатие верхней строки приближает карточку. Стрелки клавиатуры перемещают сфокусированное полотно или верхнюю строку карточки. Раскладка, масштаб и положение просмотра сохраняются в localStorage отдельно по аккаунтам. Сохранённые данные не меняют зависимости. Блокировка localStorage оставляет карту работоспособной в памяти.

Проверки геометрии и целостности примера: `npm run test:web`. Проверка взаимодействий требует настоящего браузера.

Карточки растут по содержимому: все Ходы открыты, внутренней прокрутки нет. ResizeObserver измеряет высоту после готовности шрифта и при изменении текста. Реальные границы используются в первоначальном расположении, точках линий, приближении карточки и общем обзоре. Раскладка версии 1 мигрирует в версию 2: только пересекающиеся выросшие карточки сдвигаются вниз; остальные координаты сохраняются. В версии 2 ручное размещение сохраняется точно.

Статусы следуют контракту Elements: Элементы draft/active/completed; Ходы planned/claimed/succeeded. Исторический completed у Хода отображается как succeeded. Черновик/план имеет серый пунктир и значок окружности, работа — янтарную рамку и значок запуска, завершение — зелёную рамку и галочку. Подпись дублирует цвет. В demo явно указан подтверждённый completed у четырёх Элементов, статусы всех Ходов остаются completed. Другие состояния проверяются отдельным тестовым набором, который не подключается к странице.
