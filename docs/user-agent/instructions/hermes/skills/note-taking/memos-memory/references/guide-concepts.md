## Возможности и границы
1. **Текстовая память**: исходные фрагменты диалогов, извлечённые факты, предпочтения, знания, опыт инструментов и навыки — зависит от включённых компонентов. Запись имеет ID, текст и metadata: происхождение, время, тип, статус и другие поля.
2. **MemCube**: контейнер/область памяти для пользователя, агента или проекта. Чтение и запись задаются явными списками кубов. Куб не равен текущему контекстному окну модели.
3. **MemReader**: нормализация входа, разбиение на части, формирование воспоминаний. Fast сохраняет текстовые фрагменты и эмбеддинги без LLM-извлечения; fine вызывает LLM и извлекает структурированные факты. Мультимодальность требует подходящего Reader/моделей и не гарантируется одной установкой API.
4. **Recall**: поиск кандидатов, фильтрация, ранжирование и ограниченный отбор для контекста. Архивировать весь диалог и подгружать весь архив в каждый ответ — разные вещи. Точность поиска не гарантирует истинность факта.
5. **MemScheduler**: фоновые очереди и обработчики для чтения, обновления, организации памяти и других задач. Реальная очередь/набор обработчиков определяются конфигурацией; наличие status endpoint не доказывает работающую консолидацию.
6. **MemFeedback**: исправления естественным языком, дополнение, массовое переименование и эволюция предпочтений. Коррекция может архивировать старую запись и создать новую; это не простой SQL UPDATE. Массовую область сначала согласуй.
7. **Жизненный цикл**: актуализация, объединение, архивирование и удаление. WorkingMemory, LongTermMemory и UserMemory — категории; activated/archived/deleted — отдельная ось статуса. Облачные Generated/Expired/Frozen не являются автоматически допустимыми значениями локальной схемы.
8. **Activation/KV-cache**: поддерживаемая проектом работа с промежуточными состояниями совместимой модели. Это не обычный текстовый recall и не автоматическое ускорение удалённого Codex/API.
9. **Parametric memory/LoRA**: направление проекта; прочитанная официальная страница помечает его Coming Soon. Не обещай обучение весов или hot-swap в установленной системе.
10. **Перенос/экспорт**: SDK описывает сериализацию MemCube/графа. Чтение REST-записей — не обязательно полный backup БД, отношений, очередей и файлов. Изменение embedding-модели/размерности требует плана переиндексации.

Все возможности проекта отделяй от подтверждённых возможностей локальной установки. Не копируй старый Neo4j/docker рецепт поверх работающего Supabase-сервиса.
