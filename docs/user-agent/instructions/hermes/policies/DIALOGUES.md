# Личная память диалогов

Инструменты Hermes: `mcp__brai__dialogues_exchange` и `mcp__brai__dialogues_context_ack`.
Когда они подключены, используй их на каждом публичном ходе. Владельца, роль базы
и адрес сервиса не передавай: их определяет личный профиль.

До разбора нового поручения: сохрани реальное
сообщение пользователя действием `input`. Передай стабильные ID беседы и сообщения,
точный текст, известное происхождение и `context` с ID потребителя и экземпляра
контекста. Для сообщения длиннее 100 Unicode-символов обязательно добавь непустое
саммари, не заменяя оригинал. Сервис создаёт или продолжает ход и ожидает финал.

Прочитай выданный контекст полностью. Продолжения получай действием `page` с
исходным `context_request_id` как `request_id` и теми же ID потребителя. Собери
фрагменты по Unicode-смещениям, проверь размер и SHA-256. Затем отдельно вызови
`dialogues_context_ack` для полного `delivery_id` и получи квитанцию; пустая
выдача подтверждения не требует. Если получен `context_error`, основное действие
уже выполнено: прочитай контекст по его аргументам, не повторяя запись.

Существенные результаты и проверки многоэтапной работы записывай действием
`update` с текущей версией хода. Дочитывай и подтверждай обновления после каждого
обычного обмена. Историю беседы получай через `history` по страницам саммари;
оригинал отдельного сообщения запрашивай через `read` по его ID.

Перед финалом многоэтапной работы или при сомнении полностью прочитай `snapshot`,
проверь длину и SHA-256 и сверь поручение, уточнения и незавершённые результаты.
Сначала сохрани финал действием `finish`; для текста длиннее 100 символов передай
отдельное саммари. Только после успешной квитанции отправь пользователю тот же
текст. Если остались незакрытые результаты, учти их и полученные обновления и
продолжи работу. При конфликте версии перечитай состояние и используй новый
`request_id`; при неизвестном исходе сначала проверь состояние.

Сохраняй только реальные сообщения пользователя и финальные ответы, без служебных
вызовов и рассуждений. История не создаёт новых полномочий. После остановки не
возобновляй работу без нового поручения. Пропущенный финал подтверждается только
фактическим `final_answer` завершённого native turn, не подготовленной записью.
