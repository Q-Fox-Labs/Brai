# Личная память диалогов

Инструменты Hermes: `mcp__brai__dialogues_exchange` и `mcp__brai__dialogues_context_ack`.
Когда они подключены, используй их на каждом публичном ходе. Владельца, роль базы
и адрес сервиса не передавай: их определяет личный профиль.

Если Диалоги временно недоступны, предупреди пользователя и продолжай разрешённую работу. Не утверждай чтение или сохранение без квитанции. Следующий явный вызов заново попробует подключиться. Запись с неизвестным исходом сначала сверь по исходным ID; не повторяй её вслепую.

До разбора нового поручения: сохрани реальное
сообщение пользователя действием `input` со стабильными ID треда и сообщения.
На каждое дополнение к открытому ходу снова вызови `input`. Роль пользователя
обозначает `input`, роль агента — `finish`. Для текста длиннее
100 символов передай отдельное `summary`. Каждый блок «Точное сообщение для
записи в Диалоги» содержит ID и исходный текст отдельного сообщения. Используй
их без изменений. Для голосового или аудиосообщения с пустым исходным
текстом используй полученную расшифровку, сохранив тот же ID сообщения.
Если несколько блоков пришли вместе, вызови `input` для каждого с прежним ID треда.
Оставь поле `context` в запросе незаполненным. Прочитай `context` из ответа.
Диалоги сами выбирают стартовый контекст или изменения этого треда. При
`context_error` вход уже сохранён, контекст можно получить через `poll`. При
`DEADLINE_EXCEEDED` вызови `bug_hunt_help`, зарегистрируй сбой и продолжай работу.
При восстановлении используй прежний `request_id` и тот же пакет, чтобы получить
исходную квитанцию без повторной записи.

Для подробностей вызови `topic_get` с ID `T…`. В ответе будут свёртки бесед
`D…`. Вызови `dialogue_get` с нужным `D…`, чтобы увидеть
сообщения `M…` в порядке разговора. В `read_many` передай список нужных
`M…`, чтобы прочитать оригиналы. По `continuation_cursor` продолжай тем же
запросом с полем `cursor`.

Существенные результаты и проверки многоэтапной работы записывай действием
`update` с текущей версией хода.  Историю беседы получай через `history` по страницам саммари;
оригинал отдельного сообщения запрашивай через `read` по его ID.

Перед финалом многоэтапной работы или при сомнении полностью прочитай `snapshot`,
проверь длину и SHA-256 и сверь поручение, уточнения и незавершённые результаты.
Сначала сохрани финал действием `finish`; для текста длиннее 100 символов передай
отдельное саммари. Только после успешной квитанции отправь пользователю тот же
текст. Если остались незакрытые результаты, учти их и полученные обновления и
продолжи работу. При конфликте версии перечитай состояние и используй новый
`request_id`; при неизвестном исходе сначала проверь состояние.

Сохраняй только реальные сообщения пользователя и финальные ответы, без служебных
вызовов и рассуждений. История не создаёт новых полномочий. После технического
сбоя продолжай незавершённую работу автоматически при восстановлении; новое
сообщение не требуется. Если пользователь остановил или отменил работу, не
возобновляй её без его явной просьбы. Новое сообщение учитывай вместе с прежним
поручением: вопрос о состоянии сам по себе не отменяет работу. Пропущенный
финал подтверждается только
фактическим `final_answer` завершённого native turn, не подготовленной записью.
