# Изменение и удаление памяти

Читай перед записью, исправлением, удалением, передачей или перенастройкой памяти.

Массовая очистка по обычному «забудь всё», «начнём с нуля», «передай проект» запрещена. Запрет охватывает все кубы/большой набор записей, БД/каталог, массовый feedback/delete, перебор IDs точечным forget, SQL DELETE/TRUNCATE и локальные файлы. Не обходи отказ другим инструментом или ролью.

При явном запросе владельца:
1. Без записи покажи точную область: профиль, владелец, кубы/хранилища и количества; объясни необратимость, последствия и границы.
2. После предупреждения получи ОТДЕЛЬНОЕ подтверждение владельца и явное разрешение разовой разблокировки через штатное подтверждение/clarify или отдельное однозначное сообщение. Не подставляй согласие; «сделай всё» и прежнее подтверждение недостаточны.
3. Выполни только согласованную операцию, сразу верни `bulk_clear_locked=true` и проверь результат. Постоянно защиту не отключай.

Точечное удаление явно названного воспоминания допустимо в согласованной области, но не для полной очистки перебором.

В `memos-rest.json` purge/handoff проверяют `bulk_clear_locked` под блокировкой и отказывают даже при старой CLI-строке подтверждения. Обычный запрос не разрешает менять флаг. Это защита адаптера/агента, не запрет системному администратору с доступом к БД.

Перед pause/resume, изменением SQL-прав, передачей или восстановлением читай [MEMORY_OPERATIONS.md](MEMORY_OPERATIONS.md). Состояние проверяй по живым флагам и backend, не по описанию прежней очистки. История Telegram/Hermes, логи, snapshots и бэкапы требуют отдельного согласования; очистка кубов их уничтожение не доказывает.
