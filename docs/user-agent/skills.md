# Навыки пользовательского агента

Системные навыки общие для всех пользователей. Они подключены только для чтения: пользователь не может удалить, изменить или выключить их. Личный навык не подменяет системный при совпадении имени или пути.

Тексты продуктовых навыков и справочники хранятся как документация и не входят во входы сборки или payload Hermes. Оператор обновляет один защищённый каталог для всех профилей без сборки и перезапуска шлюза. Скрипты остаются в [коде расширений](../../services/hermes/extensions/README.md) и проходят выпуск кода.

## Личные навыки

Скажите агенту «создай мне навык…» или «установи этот навык только мне» и передайте его текст. Агент использует штатный skill_manage: create для SKILL.md, write_file для справочников и скриптов. Импортируемый материал сначала читается и проверяется; установка не означает разрешение запускать его программы.

Новые навыки сохраняются только в HERMES_HOME/usercustom/userdata/skills текущего пользователя. Другие пользователи их не видят. Эти файлы не входят в исходники Brai, общий каталог или Git. Пользователь может менять и удалять свои навыки; обновление системы сохраняет их. Для личного варианта системного навыка нужно отдельное имя.

## Установка системных текстов

Оператор передаёт tools/skill_docs.py каталог Git, полный SHA коммита документации и отдельный защищённый каталог. Режим --system допускает только Root; plan не пишет файлы, apply меняет только проверенные тексты и квитанцию, verify отдельно сверяет установленный набор. Квитанция находится в docs/skill-documentation.json. Первое применение создаёт общий набор, повторная установка кода только проверяет существующую документацию.

Установщик читает только UTF-8 .md и .txt двух каталогов навыков, без выполнения кода из Git. Неизвестная локальная правка останавливает обновление. Прежние байты сохраняются в backups/; ошибка применения возвращает собственные записи. Исчезнувшие тексты сохраняются; скрипты и личные дополнения не удаляются. Прежние одиночные установки поддерживают отдельный режим без --system и первичное adopt-existing.

Все профили читают один системный набор через skill_view. Код движка сохраняет исходные встроенные навыки как общий защищённый резерв; продуктовая редакция с тем же именем имеет приоритет. Обновление такой редакции проходит через документацию. Скрипты подключаются из принятого кода только для чтения. Базовые политики и контекст остаются в поставке адаптера.

Новое чтение получает установленные байты; уже загруженный текст может оставаться в контексте разговора. Commit документации сам по себе не обновляет установленную копию.
