# Документация Brai

Прочитай этот документ перед работой с Brai. Он задаёт карту продукта и порядок поиска сведений; затем открывай только нужные разделы.

Brai — набор приложений, сервисов и адаптеров с явными контрактами. Исходники приложений находятся в `apps/`, сервисов — в `services/`, рецепты внешних зависимостей — в `dependencies/`, общие средства поставки — в `deploy/`. `component.json` рядом с компонентом описывает его ID, зависимости, проверки и состав поставки. Наличие исходников не означает, что компонент включён в установленном экземпляре.

| [Пользовательский агент](user-agent/README.md) | Поведение агента, поставляемые инструкции и личные дополнения |

## Порядок чтения

1. Найди компонент в индексе: там кратко указано его назначение.
2. Прочитай карточку: возможности, использование и ограничения.
3. Для изменения реализации или технического подключения открой README рядом с компонентом, затем его контракты и схемы.

Справочные карточки описывают поддерживаемые возможности. Целевые требования помечаются отдельно и не означают готовность функции. Технические определения принадлежат владельцу компонента; другие документы ссылаются на них.

Тексты в [инструкциях агента](user-agent/instructions/README.md) загружаются в его рабочий профиль и влияют на поведение. Остальная документация служит справкой. Личные дополнения в `user-agent/usercustom/` не входят в Git и поставку. Секреты, память и переписка хранятся отдельно.

Документация сопровождает соответствующую версию продукта. Изменение возможности требует проверки карточки и технического описания; новый компонент получает запись в индексе, карточку и технический README. Внутренние процессы разработки и конфигурация конкретных серверов не являются частью этой документации.
