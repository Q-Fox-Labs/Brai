# Авторизация

ID: `auth`. Описывает компонент в исходниках; его включённость проверяется в своём экземпляре.

## Назначение и возможности

Отправляет код входа по почте, проверяет его, создаёт сессию и завершает её.

При явной настройке общего входа передаёт действующую сессию основного DEV в разрешённое превью через одноразовое подтверждение. Повторный код из почты для каждого превью не нужен; cookie каждого адреса остаётся отдельной.

При Telegram-идентичности профиль может иметь до двух равноправных аккаунтов. Привязкой и отвязкой управляет агент с явным подтверждением пользователя. У администратора должен оставаться хотя бы один канал связи; остальные могут отключить все, сохранив профиль и данные.

## Использование

Используй форму входа Web. После неопределённого результата входа сначала проверь текущую сессию; повторная отправка кода — отдельное действие.

## Ограничения и связи

Принятие письма провайдером не гарантирует доставку в ящик. Доступность зависит от почтовой конфигурации экземпляра.

## Четыре роли

Auth поддерживает создателя, администратора, пользователя и гостя. Гостевой доступ выдаётся приглашением; вход на сайт для гостя закрыт. Роль и применение профиля имеют отдельные состояния. [Правила ролей и смены доступа](../../services/auth/ROLES.md).
