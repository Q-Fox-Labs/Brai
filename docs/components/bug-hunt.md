# Наблюдения о сбоях

ID: `bug-hunt`. Включение зависит от установки.

## Возможности

Постоянная подсказка агента — одна строка. При сбое bug_hunt_help возвращает
подробные правила и пример по запросу, не создавая обращение.

Агент сообщает конкретное несоответствие ожидаемому результату и получает
квитанцию сохранения. Пользователь видит свои обращения в разделе
«Наблюдения». Проверяющий может разобрать, архивировать или вернуть карточку
в работу с обязательным объяснением.

Каждое обращение остаётся непроверенным наблюдением. Архивирование не доказывает,
что дефекта нет. Сервис не расследует и не исправляет ошибки автоматически.
При потере ответа агент сохраняет request_id и повторяет тот же запрос.

Поиск находит свои наблюдения по словам и кодам. Одинаковые проявления можно
собрать в обратимую группу, сохранив каждое обращение и его ручное состояние.
Похожие случаи и предварительные метки Jev помогают разбору, но не подтверждают
ошибку. Пользователь видит источник метки, ограничения и неполное покрытие.
Ручное решение сохраняет приоритет. Фоновая обработка включается отдельно.

## Связи и ограничения

Данные пользователей раздельны; права проверяет Auth. Личный Hermes сообщает
через доверенный broker. Необязательные доказательства — только собственные
готовые файлы Artifacts. Тексты диагностики не исполняются и не открывают пути.

[Технический README](../../services/bug-hunt/README.md).
[Индекс компонентов](README.md).

Классификация Jev может автоматически готовить технические поля новых
обращений по защищённой политике и разрешениям владельцев. Ручная подготовка
каждого обращения не требуется. Исходники сохраняются; результат остаётся
предварительной меткой, без подтверждения бага.

При исчерпании дневного лимита модели обращение сохраняется и ждёт следующего
окна обработки. Это возможно и для новых обращений. Готовый поиск и готовая
классификация проверяются отдельно; отсутствие метки не означает отсутствие бага.
